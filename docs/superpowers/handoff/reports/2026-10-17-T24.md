## Source and dependency integrity

Assembly requires a real Git root and records current source bytes, source
commit, dirty state, included modes and explicitly approved assets. It excludes
Git metadata, credentials directories, virtual environments, generated native
builds, caches, outputs and extension binaries. Source collection detects build
markers in nonstandard directories, rejects escaping links and preserves
legitimate test/native benchmark assets. Paths and source inventory are checked
again in the staged payload. Before publication, the collector rechecks source
bytes, HEAD, tracked status and index identity so a changed checkout is not
silently labeled with an earlier provenance record.

Native targets must match the actual OS, architecture and Python minor. The
manifest records the target's accepted wheel tags and system prerequisites.
The compatibility route can select foreign Python wheels but does not advertise
a native extension. Its host Python-wheel builder does not execute the foreign
uv wheel; target and host build-tool compatibility are checked separately.

The original `uv.lock` is required and checked against the current project.
Native export includes the native and dev groups. Wheel selection uses the
export's exact pins/hashes and the actual lock's binary-wheel URLs. Every
selected wheel is checked for target tags, SHA-256, metadata identity, archive
paths, required Python, licenses where required, and active dependency edges,
including extras. Source-only resolution and tool/application pin conflicts
fail explicitly.

The supplemental tool lock is produced from explicitly selected local wheels.
It covers uv, pip, setuptools, wheel and the real PEP 517 dependency closure.
The invoked uv must match its exact selected version. The project lock is never
regenerated by this route. Tool hashes and uv license evidence travel with the
bundle.

Full mode retains the complete resolved closure. Slim mode removes only its
explicitly enumerated wheels after resolving and validating the complete graph;
the manifest retains exact external versions and a pending-T25 profile. The
checker can rehash bundled wheels. It cannot rehash omitted external wheel
bytes or prove the target's imported scientific provider; that is a mandatory
T25 check, especially for NumPy/BLAS identity.

Successful assembly retains source and wheel inventories, exact lock hashes,
command/status evidence and dependency metadata. The source checker validates
the actual files against these records, including native inputs and file modes.
`native_source_build=true` describes the payload and prerequisites for a future
local build. It does not mean an extension was built, installed, or qualified.

the public schema, collectors, payload checker, wheel and marker handling,
supplemental preparer, wrappers, documentation and inert test fixtures. The
review resolved these concrete issues before delivery:

- Target uv is kept out of the host's Python-only wheel build environment.
  Actual host tags, Requires-Python and host dependency edges are checked before
  attempting that route; target compatibility alone is insufficient.
- Both the independent flat benchmark model and the selected versioned
  model/state assets are required. Native source hashes follow the existing
  runtime fingerprint convention, including excluded directories.
- Strict target/tag grammar, wheel/dist-info identity, source modes, generated
  build roots and fixed root-member file types reject malformed payloads.
- Sidecar schemas and statuses cannot promote assembly to native execution or
  installation qualification. Current source and Git index/status records are
  rechecked before archive publication.
