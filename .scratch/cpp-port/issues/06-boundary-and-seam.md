# Граница порта и форма артефакта: что в native, кто владеет циклом

Type: grilling
Status: resolved
Blocked by: 01, 02, 03

## Question

Где граница между native и Python и в какой форме существует нативный артефакт? Решить:

- Какие модули уходят в native: runtime loop (`physical_runtime`, `ride_sim`), контроллер райдера + QP-аллокация, tyre/контакты/drivetrain per-step, запись телеметрии — по фактам из «Анатомии времени шага» (портировать то, где время, не «всё»).
- Что остаётся Python в каждой форме: MJCF-билдер/экспорт, terrain-генерация, viz, CLI.
- Форма артефакта: Python-extension (nanobind/pybind11) vs standalone бинарь vs native-библиотека + тонкий клиент — обе ветки в скоупе, выбрать с аргументами.
- Кто владеет sim-циклом и mjData: если extension — цикл внутри extension с колбэками или Python дёргает шаги? Учесть ответ «Альтернатив MuJoCo» — меняет ли движок саму границу.

## Context pointers

- Модули и размеры: `src/bike_sim/` (`sim/` 21K LOC, `physics/` 6.2K, `mujoco/` 3.2K, `terrain/` 3.3K, `viz/` 1.7K, `cli/` 1.3K).
- Consumers: live ride-viewer (`src/bike_sim/sim/ride/viewer.py` — passive viewer Python) и batch research (`src/bike_sim/sim/research/environment.py`).
- Ответы-предпосылки: билеты «Анатомия времени шага», «Нативный стек замен», «Альтернативы MuJoCo».

## Answer

**Решение: граница по такту выполнения; нативное ядро-библиотека с двумя фронтами (nanobind extension + standalone CLI); шов на intent-тике; mjModel/mjData — собственность ядра, Python видит zero-copy views + командную очередь.**

### Граница по оси времени

В native уходит всё, что вызывается на физическом шаге или контрольном тике — по «Анатомии времени шага» это ~85–90% стоимости:

- цикл рантайма (`physical_runtime`, `ride_sim`);
- все писатели сил: tyre, пад-опоры райдера, drivetrain/клатчи, подвеска, сопротивление, тормоза, envelope;
- контроллер райдера целиком (closed-form spindle + legacy QP-ветки);
- телеметрия/энергоучёт/period-batch (attachment raws, welds, tire channels, energy, `evaluate_period`) — с ленивой/батч-семантикой по «Планке корректности»: считать можно лениво, публиковать обязан весь контракт;
- рекордер (каналы, децимация, CSV);
- intent-resolution: программы райдера исполняются нативно как данные+оценщик — иначе standalone не может прогнать эпизод.

Python сохраняет всё вне такта: MJCF-билдер/экспорт (источник модели — extension получает XML и грузит `mj_loadXML`), terrain-генерация, viz (matplotlib/plotly по CSV), CLI-оркестрация, кампании исследований, тесты/оракул.

### Форма артефакта: ядро + два фронта

Портируемый код — нативная библиотека (C++17+, CMake/clang, macOS arm64; Eigen, fmt; QP — по «Стеку замен»). Поверх неё два тонких фронта:

- **nanobind-extension** — Python хозяин процесса: интерактивный viewer, исследовательские прогоны, среда эквивалентности (побитовый шов — слой 1 «Планки корректности»).
- **standalone CLI** — владеет эпизодом целиком: сценарий (конфиг + программа райдера как данные) на вход, CSV-запись на выход; headless batch; внутренний thread-pool для параллельных rollout'ов без GIL.

Дилемма «extension ИЛИ standalone» не принимается — это один код с двумя входными точками; ledger взвешивает формы «гибрид/полный» против stay целиком.

### Шов: intent-тик (10 мс)

- Интерактив (extension): Python вызывает `advance()` раз на intent-тик — ~100–200 кроссингов/с, пренебрежимо против ~2000/с per-step. Внутренний цикл (шаги, контрольные тики, период-батч) — целиком native.
- Интерактивные действия (damper clicks, air pressure, тормоз/педали от ввода) — командная очередь, применяется на границе тика; Python пишет состояние только между тиками — та же дисциплина, что сегодня.
- Batch (standalone/episode API): сценарий внутрь, запись наружу; тот же внутренний цикл без шва вообще.
- Пейсинг real-time: в extension — Python-пейсер вызовов `advance()` (viewer уже владеет циклом); в standalone — внутренний wallclock-пейсер по необходимости.

### Владение данными

- `mjModel`/`mjData` — собственность нативного ядра во всех формах.
- Чтение: zero-copy numpy-view на поля `mjData`/каналы (viewer-данные и телеметрия без маршаллинга; указатели `mjData` стабильны между вызовами).
- Запись: только entry-points/очередь на границах тика — шов остаётся прозрачным для побитовой проверки (слой 1 планки).
- **Viewer в extension**: Python passive viewer рендерит локальный replica-`mjData` на той же модели: per-frame копия qpos/qvel (+ `mj_forward` для позиций сцены) — ~60 копий/с на nv=26, тривиально. Нативный `mjData` в Python-viewer напрямую не передаётся.
- Standalone viewer — опциональный native-рендер (glfw + `mjv`/`mjr` по образцу `simulate`), не требование.

### Двигатель и граница

Ответ «Альтернатив MuJoCo» границу не меняет: MuJoCo — библиотека под швом в любой форме; bespoke-вариант просто заменяет движковый слой внутри native-ядра (Pinocchio + свой constraint-слой), Python-сторона идентична.

### Следствия для карты

- Форма «гибрид» уточнена: это не «часть модулей Python», а общий native-цикл под Python-процессом; «полный» отличается только фронтом и переносом оркестрации — разница между формами мала, что само по себе пункт ledger (переход гибрид→полный — добавление standalone-драйвера, не новый порт).
- Parallel batch-rollout'ы: нативные потоки внутри ядра (эпизоды независимы) — работает в обеих формах; снимает GIL-ограничение, множитель throughput помимо per-step RTF.
- Стек зафиксирован: **C++**17+, CMake, clang, macOS arm64; Eigen/fmt/CLI11/Catch2/nanobind по «Стеку замен». Вопрос «C vs C++» закрыт — Eigen и nanobind требуют C++.
