# Retained reference data — provenance and the immutable reference model

This file records where the Python-free product's retained oracle data came
from, which platform/toolchain/provider identity each set carries, and the
rules for reading or extending it after
[ADR-0003](../adr/0003-native-authoritative-python-removal.md). It is also
the declared documentation replacement for the retained research tooling
that produced some of these artifacts (`migration/python-removal.json`
exempt rows name this file).

## The reference model after ADR-0003

During the migration a live Python oracle compared the C++ port bitwise at
every gate. T63 removed that runtime: there is no interpreter, no oracle to
invoke and no way to produce new oracle bytes on this tree. What remains is
the *captured* oracle — committed per-platform reference data plus the C++
tests that consume it:

- **The gate is**: in-build determinism (two runs of the same build agree
  bitwise) plus equality against the committed golden for the *running*
  platform.
- **Reference data is immutable.** A captured artifact is never edited in
  place, never "fixed up" for a new platform and never regenerated by hand.
  A new generation arrives only from a new authorized measurement on the
  target platform, recorded with its own provenance.
- **Platform identity is binding.** A golden captured under
  `darwin-arm64` is authoritative only for macOS arm64 with the recorded
  toolchain/numerics provider; `linux-aarch64` goldens carry their own
  toolchain/provider. A mismatch is a report to the platform owner, never a
  reason to transplant bytes between platform directories or to relax a
  comparison.

## Golden fixtures — `tests/fixtures/golden/<platform>/`

| Location | Contents | Provenance |
|---|---|---|
| `darwin-arm64/` | Per-test captured oracle outputs (`.bin` + `.json`) under directories named for the deleted `tests/reference/test_native_*.py` harness that produced them | Captured on macOS arm64 (AppleClang, Accelerate numerics provider, MuJoCo 3.12.0) during the T-series porting tasks; the pytest harness compared the live Python oracle against the extension and froze its outputs |
| `linux-aarch64/` | The same test-name-keyed captures for the Linux aarch64 lane | Captured in the pinned Ubuntu 24.04 aarch64 container (Clang 18/GCC 13 lanes, NumPy-wheel OpenBLAS ILP64 provider); see the container lane contract in [development/linux.md](../development/linux.md) (deferred, pre-removal) |
| `episode/`, `pneumatic_tire/`, `pneumatic_wire/` | Cross-platform frozen episode/tyre fixtures shared by both platform trees | Captured oracle episodes/material fixtures; consumed through each platform's own tests |

Directory names preserve which test file's values a capture belongs to.
Files inside a platform directory are inputs to the C++ port of that test —
they are read, never written, by the test suite.

## Other reference surfaces

- `tests/fixtures/portability/build_id_vectors.json` — pins the
  `macos-<build>+accelerate-<uuid>+sdk-<build>` provider-identity spelling
  consumed by `native/cmake/BikeProviderIdentity.cmake`.
- `tests/fixtures/migration/`, `tests/fixtures/platform-recordings/` —
  retained migration recordings and platform evidence used by migration
  checks; provenance is recorded per task in
  `migration/cpp-linux-completion-evidence.md`.
- `native/numerics.lock.json` — the committed measured numerics record
  (per-platform `records[<platform>]`). Consumed `RECORD_ONLY`; the live
  probe that produced it was removed at T63. Its content rule and update
  discipline are documented in
  [development/numerical-profiles.md](../agents/native-numerical-profiles.md)
  §9.
- `native/dependencies.lock.json` and `.deps/` — schema-2 native dependency
  archives (MuJoCo 3.12.0, DuckDB, GLFW, the NumPy-wheel OpenBLAS provider
  and its `libgfortran` companion), verified by archive and member hash.
  Provenance: [native/dependencies.md](../../native/dependencies.md).
- `tools/proto_native_bench/artifacts/` — BIKEST02 state bundles written by
  the deleted `dump_model.py` writer; read-only inputs to `native_bench`
  and the benchmark CTest nodes. See
  [tools/proto_native_bench/README.md](../../tools/proto_native_bench/README.md).

## Retained research tooling — `tools/research/`

The T63 exemption set keeps `tools/research/adjudication/` and
`tools/research/{alpine_osm_dem,lateral_digitise}/` — offline
recomputation scripts plus their pinned `data/` artifacts — outside the
product runtime and every delivery surface. They are not invoked by any
build, test or packaging surface, and running them requires an external
interpreter supplied by the operator. Their role is provenance: they make
the adjudication registry verdicts and the `AlpineGenSpec` v2 statistics
reproducible, and their committed outputs (`expected/stats2_out.json`, the
digitised CSVs, the scree collections) are the reference data for
[alpine-trail-statistics.md](alpine-trail-statistics.md) and
[mtb-lateral-digitisation.md](mtb-lateral-digitisation.md). Each
directory's README records the era's invocation as `~~~`-fenced recorded
commands — they are not live product instructions.

## Rules for new reference data

1. Capture on the platform the data will qualify — a Darwin capture never
   stands in for Linux and vice versa. Record host, toolchain, provider and
   the producing commit.
2. Commit the bytes once; never edit them afterwards. Corrections arrive
   as a new measured generation alongside (not instead of) the old one,
   with its own provenance.
3. A consumer that finds a mismatch reports it — it does not regenerate,
   transplant or widen a tolerance to hide it.
4. Anything claiming to *produce* oracle data on this tree is suspect: the
   producing runtime was removed. The audits
   (`python_audit_source`, `python_audit_documentation`,
   `python_audit_package`) gate that claim at the source, documentation and
   package surfaces respectively.
