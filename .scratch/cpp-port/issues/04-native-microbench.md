# C++ microbenchmark: измеренный потолок mj_step на M4

Type: prototype
Status: resolved
Blocked by: —

## Question

Какой real-time фактор даёт нативный код там, где его можно измерить дёшево? Построить throwaway C++ harness: загрузить экспортированный MJCF (`bike-export`), цикл `mj_step` с типичной периодикой контроллера (200Гц тик) и заглушкой контрольного/телеметрийного слоя реалистичной стоимости — по данным «Анатомии времени шага» это сейчас force-writers + telemetry (~85% шага), а не QP (в дефолтном spindle-профиле QP нет; в legacy-ветках — есть, замерить оба варианта). Замерить шаги/сек и real-time фактор на Apple Silicon. Сравнить с тем же на Python `mujoco` на идентичной сцене — отделить выигрыш «native loop» от «native контрольная математика».

Результат — измеренные цифры (не оценки): голый `mj_step` Python vs C++; `mj_step` + реалистичный контрольный слой на обоих. Человек реагирует на цифры: это вход в «Синтез ledger».

## Answer

**Измерено (не оценено) на Apple Silicon M4: та же `libmujoco.3.12.0.dylib`, та же скомпилированная модель (nv=26, neq=7, welded-physical), реальное mid-ride состояние с extreme-трассы.**

Прототип: `tools/proto_native_bench/` (throwaway): `dump_model.py` снимает `model.mjb` + `state.bin`; `bench.cpp` и `bench.py` — идентичные синтетические нагрузки. Долговременная копия — ветка `proto/native-microbench` (commit `10522dc`).

### Цифры (µs/шаг, 4000 шагов после прогрева; rewind каждые 250 шагов удерживает контактный режим)

| Нагрузка | Python | C++ | RTF C++ |
|---|---|---|---|
| bare `mj_step` | 32.4 | 31.6 | 15.9× |
| glue: +3 fwd, 19 jac, 28 name2id, 8 qfrc-сборок, ~100 каналов | 144.7 | 93.4 | 5.4× |
| heavy: +efc-распаковка, 5 wrench-solve, энергоучёт, record-churn, 8×8 lstsq/10 | 214.3 | 92.8 | 5.4× |

### Что измерено

- **`mj_step` не ускоряется**: ~32µs в обоих языках — подтверждение «Анатомии». Pybind-налог ~1µs на engine-вызов (~50µs на ~50 вызовов в glue).
- **Скомпилированная телеметрия почти бесплатна на этом объёме**: heavy ≈ glue в C++ (92.8 ≈ 93.4, в пределах шума).
- **В нативном шаге движок доминирует** (~60µs из 93 — `mj_step` + forwards + jacs): дальнейший прирост внутри MuJoCo — только меньше forwards (`mj_forwardSkip`/`mj_step1+2`, полу-нативно по «Анатомии») или bespoke-движок.
- **Экстраполяция на реальный объём**: синтетическая телеметрия ~7× тоньше реальной (~1.6ms Python-клея, ~6460 вызовов/шаг). При масштабировании скомпилированной телеметрии ×5–10 нативный полный шаг ≈ **200–400µs → RTF ~1.3–2.5×** — совпадает с аналитическим потолком 2–3.5× из «Анатомии», но теперь измерено.
- Не измерено: реальный QP на тике (оценка ~5–10µs/шаг нативно), контроллер (~5–10µs/шаг), потоки для batch-rollout (отдельный множитель throughput, не per-step).

### Оговорки

- Синтетическая нагрузка — репрезентативный МИКС операций, не реальный порт: настоящий алгоритмический контент (геометрия attachments, QP, контрактные каналы) добавит сверху. Числа — доказательство механизма и порядка величин, не приёмочный критерий.
- Python-twin намеренно тоньше реального клея — цель была изолировать такс интерпретатора/биндингов на управляемой нагрузке, а не воспроизвести 1.8ms.

### Реакция человека (HITL)

Вердикт: **лучше, чем ожидал** — диапазон ~200–400мкс/шаг (RTF ~1.3–2.5×) укрепляет кейс порта в ledger. Дополнительные замеры (QP-стаб, параллельные rollout'ы) не потребовались.
