## Runtime decisions and review findings

T18 source inspection found the relevant rendering work already at interactive
boundaries. No unnecessary import rewrite or global `MUJOCO_GL` setting was
introduced. The new controls forbid actual rendering initialization, not the
mere presence of GLFW/MuJoCo bindings. The real-driver case requests the
existing valid four-step fixture; ordinary strict CLI validity stops remain
explicit expected invalid outcomes, not successful-duration evidence.

T20 keeps Apple's performance-core query on Darwin, uses process-available
CPU discovery elsewhere, and honors positive explicit job counts. Batch
retains its spawn pool. Async publication selects spawn on Linux and retains
fork on Darwin. Unsupported explicit methods fail before resource creation.
The existing module-level worker and CLI main guards remain the launch
boundaries; the actual installed wrappers still need host verification.

Resource ownership was traced beyond the process class. Driver/environment
close and failed construction now release their worker without publishing or
stepping. Native physical setup does not start an unused reference worker.
Shutdown attempts graceful exit, terminate and kill with bounded joins,
closes both queues even after cleanup errors, and retains the primary error.

The review also found that an early successful reply could be removed from
pending ownership before a later reply failed, and serialization fallback
could omit older queued periods. Pending periods now remain recoverable until
their returned batch is acknowledged. Recovery retains samples and constraint
maps from every period while calling the original publisher/accounting path
once per period. A worker publication error carries its successful prefix;
it is not mistaken for transport loss or silently replayed twice.

`bike-ride --research --async-telemetry` now passes the explicitly requested
flag into `ExperimentConfig`. Default flags and the documented delayed
observation semantics are unchanged. No claim is made that arbitrary policies
are bitwise equivalent with delayed observations.

## Installation decisions and compatibility

Native imports require the source tree belonging to the imported package and
its editable environment. A Python-only wheel does not gain native support
by pointing at an unrelated build. Selection still requires an absolute
directory and exactly one supported extension suffix, with pinned dependencies
and the selected imported path. Both fresh and cached extension imports must
match the compiled native source identity. Dynamic-loader and runtime-identity
exceptions retain their original causes and receive interpreter/SOABI,
platform, build and explicit remediation context.

`tools/dev.py` propagates an absolute `UV_PROJECT_ENVIRONMENT`, checks that the
selected interpreter matches the source environment and existing CMake cache,
and pins `Python_EXECUTABLE` when configuring. Its existing bootstrap
`uv sync --locked` behavior is retained. The documented direct source-sync
route remains `uv sync --frozen --group native`.

Doctor previously used a dependency probe that performs compile/link ABI
controls. It now performs runtime introspection in a fresh interpreter and
never invokes that compiling probe. It checks the selected import, source
and artifact identity, Python/SOABI, MuJoCo private symbols and numerical
provider evidence. It reuses the existing sanitizer policy and restores the
selected preload for its direct child, including after macOS dyld clears the
parent variable. This diagnostic is not a substitute for configure-time ABI
qualification or the native gate.

`BikeCheckContext.cmake` adds Python executable/version/SOABI, source directory
and build directory evidence while keeping schema 2 and existing fields.
Existing runtime/test context readers do not require these new fields; doctor
asks for explicit reconfiguration when installation evidence is missing.
The CMake source change changes the native source fingerprint: **reconfigure
and rebuild the selected artifact explicitly before later native tests**.
Nothing was configured or rebuilt during this work.

Physics equations, controller laws, fixed integration timing, scientific
dependency pins, recording schemas/opt-in/finalization and replay tolerances
were not changed. Viewer qualification, T21 recording acceptance and T24/T25
offline bundle work remain separate tasks.

## Pending verification after execution is authorized

Run the following only in the real source/editable environment with the
intended pinned dependencies. These commands are a handoff, not an execution
log. Select a separate native build directory per OS/environment; the names
below are examples, not measured qualified paths.

```sh
export UV_PROJECT_ENVIRONMENT=/absolute/path/to/the/project-venv
export BIKE_NATIVE_BUILD_PATH=/absolute/path/to/the/native-build
```
