## Claim-by-claim verdicts

1. **Transmission implicitly movable / null `constant_` crash: partially confirmed, scoped to misuse of a moved-from direct C++ object.** `native/src/drivetrain/transmission.hpp:37` declares neither explicit move nor copy; `OwnedData` at line 17 makes copying unavailable and movement implicit. `std::is_move_constructible_v` reports 1, copyable reports 0. A standalone `auto b=std::move(a); a.set_ratio(d,34./28.)` terminates with signal 5 under the pinned hardened libc++. However source line 146 dereferences the moved-from, now-empty `coefficients_` vector **before** line 147 calls `mj_setConst` with null `constant_`; the reported null-constant cause is not established. Current writer callers own it behind `unique_ptr` (`native/src/writers/drivetrain.hpp:107`, constructor cpp:72), and `_drive_core` constructs it locally, never moves it. No production crash established. Default moved-to state itself is valid. Decide/document move semantics as future API hardening, not a current user-path crash.

2. **`set_ratio` mutates before throwing geometry: confirmed reachable with parser-valid Python configuration.** `native/src/drivetrain/transmission.cpp:164-167` updates gearing, stored rear teeth and ratio before evaluating new geometry; `chain.cpp:51-52` throws if external tangent impossible. The parser validates cassette teeth minimum but no geometrical maximum (`policy_binding.cpp:214-236`). Repro in `drive_probe.py`: geometric kind with `ShiftingConfig(enabled=True,cassette=(24,1000),cadence_smoothing_tau_s=0.,target_cadence_min_rpm=100.,target_cadence_max_rpm=1000.)`, crank rate4 and wheel1, then `drive_prepare_pedaling({},.1)`. Raises ValueError, ratio changes 34/24→34/1000; boundary and prepared phi unchanged. `DrivetrainWriter::prepare` also commits shifter state first (cpp:183-186). Persistent mixed old/new geometry after rejected call.

3. **compute/prepare mutate before allocation failure; retry advances twice: confirmed.** `writers/drivetrain.cpp:264-267` advances pedaling/shifting before constructing `live_.last` at367 and allocating angles at431. Timestamp commit is437. C++ allocation interposer on ordinary ideal model measured54 `operator new` calls in one `components` call. Injecting first allocation failure advanced effort10→20, leaving last_time at0 and pending1. Source matches. More accessible counterexample without OOM: an unsettled pending interval at new timestamp reaches guard346 only after policy advancement; two failing attempts change effort2→3→4 while raising RuntimeError. Existing test `tests/reference/test_native_drivetrain.py:391` checks Python parity after the throw, not original-state preservation, so it passes despite both implementations doing this.

4. **settle double battery draw after throwing: conditionally confirmed; normal ideal settlement does not allocate after draw with complete diagnostics on this libc++.** Draw commits at `writers/drivetrain.cpp:491`; diagnostics writes493-498 can allocate map nodes; pending clear only502. `parse_diagnostics` accepts an empty mapping (no required-key check; drive_binding.cpp:118-187 loop), and writer restore accepts it. C++ repro restores pending snapshot with `last.clear()`, fails the third settlement allocation (index2): battery995.276→984.997, pending remains1; retry reduces to974.718. This is an allocation-failure/sparse-restoration issue. Reserved torque and battery ceiling errors occur **before** battery.draw and cannot themselves double debit (cpp:477-490). Ordinary complete ideal diagnostics had no settlement allocations, so do not claim normal repeat-settle alone double draws. Existing duplicate-settlement test passes after a successful first call.

5. **motor empty torque curve / invalid direct config: direct API hardening confirmed; normal parser rejects.** `motor.hpp:8` copies any AssistConfig without validation; `motor.cpp:12` unconditionally calls `rows.front()` when optional engaged. Direct C++ `torque_curve.emplace(); AssistController(c).ceiling(60.,2.)` terminates signal5. Python `DrivePolicies` rejects empty curve with ValueError; parser enforces two rows, nonnegative values, strictly increasing RPM (`policy_binding.cpp:249-259`), plus tau/slew/width constraints238-248. Writer and scalar-policy bridge both call parser before construction. Not a normal Python crash.

6. **pedaling/shifting constructor invariants absent: confirmed direct API concern; rejected by current Python construction path.** `pedaling.hpp:14` and `shifting.hpp:8` accept invalid typed configs without validation. Direct `PedalingPolicy({}).update(0.,4.,40.,0.,.01)` uses stop_time0 (`pedaling.cpp:88`) yielding infinite internal deceleration; `CadenceShifter({},{}).gear_ratio()` returns NaN from0/0 (`shifting.hpp:18`). Parser validates stop_time, hysteresis, mash constraints, cassette, cadence bands and cooldown/cut relationships (`policy_binding.cpp:194-236`). Config structs are publicly constructible but current production constructor flow passes validated values. Severity should reflect current caller protection.

7. **unknown motor modes silently treated as eMTB: partial, direct-profile API only.** `motor.cpp:65-73` uses final else for all profile modes beyond eco/tour/turbo. Parser rejects unknown profile mode (`policy_binding.cpp:273-275`). Without profile, any mode string is explicitly permitted by unchanged Python `src/bike_sim/physics/motor.py:48-53`, and covered by test `(None,'custom')` (`test_native_drive_policies.py:161`). Runtime synthetic mode `'anything'` produces normal assist. Do not require blanket enum rejection: it would break documented oracle behavior. Direct unvalidated AssistConfig with profile+unknown mode still falls through to eMTB.

8. **`_drive_core` invalid kind / live model corruption: confirmed, private adapter scope.** `drive_binding.cpp:619` maps every unknown kind to ideal; function constructs transient Transmission over `owner.model()`620. Its operations change shared tendon ranges/coefficients; live writer object ratio/prepared caches are not updated or restored. Repro live ideal Stepper: `_drive_core('unknown','ratio',34/28)` succeeds; writer snapshot ratio stays34/24 while coefficient becomes34/28. Normal kind also causes this. Counterevidence: `docs/TESTING.md:211` calls it a private per-call test adapter; tests create a **bare** Stepper for it (`test_native_drivetrain.py:198-217`), and no application caller exists. Prevent adapter use on configured live writer or detach model if retaining it, but avoid presenting as ordinary tick behavior.

9. **`_drive_prepared_storage` raw addresses: factually confirmed, intentionally read-only private test instrumentation.** `drive_binding.cpp:508-521` exposes `uintptr_t` addresses and capacities; runtime addresses nonzero and stable. Tests518-558 use them to establish construction-owned storage stability and verify public snapshots do not alias. It cannot restore/dereference pointer through this API. No memory safety defect demonstrated. Address exposure/hiding debug API is a design consideration, not evidence of pointer ownership bugs.

10. **drive/policy FFI helpers copied: confirmed maintainability observation.** Compare `drive_binding.cpp:21-81` and `policy_binding.cpp:17-69`: duplicated field/section/number/boolean/integer/string/optional_num/width/result_dict logic. Some differences intentional (integer overloads, handle bool overload). No bug follows from duplication alone. Runtime tests show both scalar config number helpers reject bool.

11. **truthiness bool conversion: rejected.** Drive bool helpers explicitly check exact bool (`drive_binding.cpp:53-58`), scalar policy plain bool args rely on nanobind exact PyTrue/PyFalse caster (`.venv/.../nanobind/include/nanobind/nb_cast.h:269`). Runtime `assist_step(...,braking=v,...)` rejected1,0,'true',[],None,np.bool_(True) with TypeError. Binding uses bool type, not Python `bool(x)` truthiness. Python parity does differ in error type and `np.bool_` acceptance for assist, but no arbitrary truthiness.

12. **dict nonstring-key exception inconsistency: confirmed minor FFI validation issue.** `drive_binding.cpp:260` and190 cast keys to std::string without isinstance/cast_error translation. Runtime `{1:0}` control or `state['last'][1]=0` raises RuntimeError `std::bad_cast`; ordinary invalid values raise ValueError. Parser runs before writer mutation, so no state corruption from this exact error. Add strict key validation for predictable public exceptions.

13. **raw new before capsule can leak: confirmed conditional exception-safety gap by implementation and library source, not fault-injection reproduced.** `drive_binding.cpp:96-99` allocates array then constructs capsule without RAII guard. Nanobind `nb_types.h:761-763` calls PyCapsule_New and `raise_if_null`; failed capsule creation does not invoke provided cleanup because ownership was never acquired. A Python allocation failure between new[] and capsule ownership leaks the C++ array. Once capsule exists, ndarray creation failure is guarded by the local capsule. Similar code exists in binding.cpp:58-60 and contact_binding.cpp:46. Repro claim should be qualified to the capsule allocation failure, not ordinary ndarray export failure.

14. **drive arrays lack owner / use-after-free: rejected.** `drive_components` and settle exports call `owned` capsule helper (drive_binding.cpp:570,580); snapshots same. For `qfrc_applied`/`actuator_force` getters604-613, an empty explicit ndarray owner is supplemented by nanobind `def_prop_ro` default `reference_internal`. Library `nb_class.h:558` injects that policy; `nb_ndarray.cpp:1201` retains cleanup self. Runtime `sys.getrefcount(n)` increases by1 while either property array alive. Returned array base is memoryview. Existing `test_set_inputs_cross_aliases_and_ownership` passes and deletes owner while component arrays survive. No UAF established.

15. **hot path ~50 allocations / deep copies: allocation count confirmed; RT violation scope overstated.** Interposer measured54 native allocations on ideal compute, excluding Python dictionary/array output. Most come from fresh `Diagnostics` map at writer.cpp:367-430. Probe path copies live_/policy configs (`cpp:224-248`), including map/vector/optional curve where present. Normal advance path does not deep-copy all DriveSnapshot state each time. `docs/TESTING.md:123-125` marks only Stepper step/forward as nonblocking;272 explicitly says these P3 gates do not establish allocation-free P4 tick. Current implementation genuinely allocates; future full tick RT work needed. Existing stated step/forward guarantee is not disproved.

16. **optionals / sentinels / string enums / magic component indices: source facts and maintainability opinions, not automatic defects.** Explicit optional fields carry uninitialized/probe/absent-topology states required by `docs/TESTING.md:240-255`; prepared sentinel owns fixed buffers and has focused regression tests. State enums are parsed for public drive mode/model, shifter direction, pedaling mode; synthetic assist mode is deliberately open. `components_[0..2]` corresponds construction order at writer.cpp:89-94 and compute.cpp:290-308. Reordering is fragile but no mismatch exists today. Geometry coefficient -1 sentinel is checked at transmission.cpp:64. A refactor needs preserved schemas/parity, not wholesale optional or string elimination.

17. **drivetrain header not self-contained: rejected on current pinned toolchain.** `native/src/writers/drivetrain.hpp` compiled standalone via `/usr/bin/c++ -std=c++23 -isysroot /Applications/Xcode.app/Contents/Developer/Platforms/MacOSX.platform/Developer/SDKs/MacOSX26.5.sdk -I. -I.venv/lib/python3.14/site-packages/mujoco/include -x c++ -fsyntax-only native/src/writers/drivetrain.hpp`. Only expected pragma-once-main-file warning, exit0. Project headers supply all names (std::span via chain.hpp, std::runtime_error/string via policy_config.hpp etc.). Direct-include hygiene may still be improved, but compilation failure claim is false.

## Additional concrete issues

- **Invalid effort ceiling mutates before ValueError.** `writer.cpp:192-199` updates policy first, then nonnegative(ceiling). Runtime `drive_prepare_pedaling({},.01,effort_ceiling_nm=-1.)` with effort slew100 changes effort0→1 before raising. Validate ceiling before all stateful updates. Also prepare itself does not commit last_time, so repeated successful prepare without a components call can advance at same time; normal intended prepare+components sequence deliberately allows two-phase preparation, so design decision requires explicit contract.
- **Bool silently accepted in typed numeric vectors and optional scalar arguments.** `drive_binding.cpp:83-90` casts vector<double> directly rather than using strict number() per element. Restoring prepared Jacobian or qpos with all True succeeds as1.0. `drive_prepare_pedaling` binds optional<double> slip/ceiling directly (cpp:542-543); True ceiling accepted1.0 and slip True accepted1.0. Strict num/control validation rejects booleans, and unchanged Python scalar/array validation rejects numeric booleans. Tighten boundary validation if uniform schema intended.
- **Relational snapshot consistency not enforced.** `Transmission::validate` checks ratio positive, rear teeth minimum, widths and finiteness but not relationship to sprocket teeth/model coefficients; writer restore checks sections individually without transmission-vs-shifter ratio agreement (`writer.cpp:581-588`). Runtime state ideal ratio changed to2.0 alone accepted; subsequent compute uses boundary relative2.0 but physical tendon coefficient1.41666 and shifter/diagnostic ratio1.41666. A positive-but-inconsistent snapshot can produce wrong physics. Existing arbitrary-state replay verifies round-trip injection, not cross-field invariants. Confirm intended restore contract before restricting valid snapshot space.
