# Бриф для многодневного deep-research: шина × рельеф × сыпуха для BikeSim

Дата: 2026-10-14. Назначение: вход для внешнего исследовательского воркфлоу с ИИ-агентами
(тот же класс инструмента, что произвёл `.scratch/tire-research/` 2026-10-13: fan-out
поиска → fetch первоисточников → адверсариальная верификация → синтез с цитатами).

самодостаточное задание со своим вопросом, критерием «что считается находкой» и форматом
ответа. Углы можно запускать параллельно и в любом порядке; зависимости отмечены.

Читается вместе с: аудит `docs/superpowers/audits/2026-10-14-tire-research-vs-implementation.md`,

## 1. Контекст-пакет (вставлять в каждое задание целиком)

**Проект.** Симулятор e-MTB (MuJoCo + собственный C++ tick-path, dt 0.5 мс) для разработки
контроллера мотора против подъёма переднего колеса на крутых каменистых подъёмах.
Трасса: высокогорная, «марсианская» — крупные камни, скальные ступени и сыпуха (подвижный
щебень тонким слоем над породой); без грунта, корней, деревьев, грязи. Скорости 3–25 км/ч,
нагрузки на колесо 300–1200 Н (с рывками при наезде на камни), давление 1.2–2.0 бар,
покрышки 29×2.4 / 27.5×2.4 с грунтозацепами (Schwalbe Magic Mary / Hans Dampf).

**Что уже есть в симуляторе (не предлагать заново).** Пневматическая шина из 64/256
радиальных элементов по ±75° с законом «давление × хорда + жёсткость каркаса», Maxwell-ветвь,
рейт-независимый гистерезис, удар обода, несколько пятен контакта одновременно (камни
обтекаются геометрически — enveloping есть), щёточная модель продольного сцепления с
relaxation length и трением Стрибека, поверхности как кривые трения на **жёсткой** дороге.
Вертикаль откалибрована по Dressel & Sadauckas 2020 и Sadauckas et al. 2024
(`k(p) = 22 + 24p` Н/мм ±15 %, длина пятна 133/122 мм при 1.38/1.72 бар и 418 Н, динамическая
жёсткость 1.16–1.35, демпфирование 2–5.5 %, Crr барабана 0.0103/0.011 при 1.5 бар). Всё на C++
с побитовым паритетом к Python-референсу. Идёт переход в 3D (тор, боковые силы, развал,
боковой уклон ±15°, камни под плечом покрышки, колеи).

**Главный известный пробел.** Сыпуха — жёсткая дорога с пониженным трением; нет просадки,
сопротивления уплотнения, зарывания при буксовании, предела сцепления из прочности щебня.
Проектируется квазистатический слой Беккера конечной толщины (дизайн сыпухи §4), все
параметры **авторские**: измерений «MTB на сыпухе» не найдено.

**Что уже выяснено исследованием 2026-10-13 (не тратить бюджет на повтор, только на
опровержение, если встретится).**
- Dell'Orto 2024 (VeTyT, Zenodo 7866646/7920415, `mechmotum/Magic-Formula-89`) — единственный
  открытый датасет боковых характеристик велошин; городские/грузовые 300–500 кПа, 343–526 Н,
  насыщение не достигнуто. Не MTB.
- Chrono::Vehicle: таксономия rigid/handling/FEA; handling-шины несовместимы с деформируемым
  грунтом в его системе; enveloping Sui & Hirshey 2001 (таблица площадь→глубина) — нам не
  нужен; SCM GPU — PR #808.
- SymBRiM — только абстрактные классы шины; yamazaki-model — brush+Hertz+Stribeck без динамики;
  bicycle-kickplate-model PR #15 — комплаенс-состояние для Fz (у нас уже есть аналог).
- PINNeAPPle — Wong-Reece для лунного реголита, валидация по оцифрованным графикам.
- FEA/ANCF/XPBD — не для реального времени; офлайн-калибровка.

**Стандарты, обязательные для каждого угла.**
1. Первоисточники: статья/диссертация/репозиторий/стандарт, не обзорный блог. Для каждого
   числа — источник, страница/таблица/рисунок, единицы, условия измерения (нагрузка,
   давление, скорость, влажность, размер частиц).
2. Явно помечать: `measured` (таблица в статье) / `digitised` (считано с графика) /
   `authored` (оценка автора источника) / `extrapolated` (наш вывод).
3. Утверждение считается находкой, только если подтверждено первоисточником **и** пройдена
   попытка опровержения (второй независимый источник или прямая проверка кода/данных).
   Голосование верификаторов — записывать.
4. Для кода: клонировать и читать, а не пересказывать README; указывать файл:строки и коммит.
5. Опечатки/расхождения в источниках (DOI, фамилии, годы) фиксировать отдельным списком.
6. Если ответа нет — так и писать: «не найдено после N запросов по таким-то ключам»; это
   тоже результат, он закрывает вопрос для проекта.

**Формат ответа каждого угла.** (a) 5–15 находок: утверждение, уверенность, доказательство,
источники; (b) таблица параметров с единицами, полосами и пометками провенанса — в виде,
пригодном для прямого переноса в `SurfaceSpec.soft` / `tyre_lateral_reference.json`
(JSON-фрагмент приветствуется); (c) что это меняет в дизайне сыпухи/3D-шины (конкретно: какой
пункт спецификации, в какую сторону); (d) открытые вопросы; (e) список опровергнутого.

## 3. Углы исследования

### A. Террамеханика тонкого сыпучего слоя над твёрдым основанием (P0)

**Вопрос.** Как ведёт себя закон давление–просадка и сопротивление уплотнения, когда слой
рыхлого материала толщиной 3–10 см лежит на жёсткой породе, а штамп/колесо шириной 5–6 см
и давлением 100–200 кПа продавливает его до дна?

**Искать.** Классика: Bekker (1956/1969), Wong *Theory of Ground Vehicles* (главы о
pressure–sinkage, параметры грунтов), Reece 1965, Wong & Reece 1967 — и специально
**конечная глубина / «hardpan» / «layered soil» / «thin soil layer over rigid base»**
(в сельхоз-террамеханике есть работы о плужной подошве; в планетологии — реголит над
коренной породой; в геотехнике — bearing capacity of a thin granular layer over a rigid
base, Meyerhof). Корректировки Беккера для малых штампов (размер штампа сравним с
частицами — scale effect, Gotteland & Benoit). Slip–sinkage: Lyasko, Ding et al. 2011,
Senatore & Iagnemma, Hurrell 2025 (упоминался в PINNeAPPle). DEM-исследования колеса на
гравии/щебне с размером частиц 1–10 см.

**Находка — это.** (1) Форма закона с учётом дна (как меняется `k_eq, n` при `z → H_s`;
есть ли «упрочнение» перед дном); (2) полосы `k_c, k_φ, n, c, φ, K` для сухого угловатого
гравия/щебня с размером частиц 1–10 см, с условиями; (3) обоснованный вид slip–sinkage для
крупнозернистого материала; (4) оценка, при какой толщине слоя щебень «ведёт себя как
жёсткая дорога» (порог, ниже которого модель не нужна).

**Зачем проекту.** Дизайн сыпухи §4.1, §4.4, §8 (полосы параметров), критерий
необходимости модели.

### B. Измеренное сопротивление качению и тяга велосипеда/мотоцикла на гравии и щебне (P0)

**Вопрос.** Какие есть измерения Crr и предельной тяги/торможения двухколёсных машин на
рыхлом гравии, щебне, осыпи — с условиями?

**Искать.** Полевые измерения мощностью (power meter / coast-down) на гравийных дорогах
(gravel cycling research, Bicycle Rolling Resistance gravel/MTB tests на шероховатом
барабане и их корреляция с полем), исследования велодорожек/грунтовых покрытий
(transportation research: «rolling resistance unpaved bicycle path»), мотоциклетные
off-road/enduro испытания тяги на гравии, военные/ДОСААФ-овские данные по мотоциклам,
ADAC/TÜV-испытания, данные по инвалидным коляскам и детским коляскам на гравии (там
есть ISO-методики и цифры), сельхоз-колёса малого размера. Параллельно: измеренные `μ`
резина–щебень и «щебень–щебень» в сдвиге (geotechnical direct shear на гравии).

**Находка — это.** Числа Crr с условиями (размер частиц, толщина слоя, давление, нагрузка,
скорость); предел тяги/торможения как доля нагрузки; зависимость от давления в шине на
рыхлом (есть ли противоположный асфальту тренд — ниже давление → меньше Crr на рыхлом).

**Зачем проекту.** Стенд §7 «тяга при фиксированном проскальзывании» и §8 (Crr-ожидание
0.02–0.04 должно стать источником или быть снято).

### C. Боковые и развальные характеристики MTB-покрышек при низком давлении (P1)

**Вопрос.** Существуют ли измерения жёсткости увода `C_α/F_z`, развала `C_γ/F_z`, боковой
relaxation length и их зависимости от давления/нагрузки для MTB-шин ≥ 2.3″ при 1.0–2.0 бар?

**Искать.** Dressel 2013 (UWM thesis) полный текст и приложения; Doria et al. 2013 и
последующие работы группы Падуи (Doria, Tognazzo, Favaron, Massaro) — у них стенд для
велосипедных и мотоциклетных шин, есть off-road мотошины; Cole & Khoo 2001; Rothhamel 2024
(упомянут в `parameters.py` bicycle-kickplate-model — найти, что это); Bulsink/Bulsink et
al. (TU Delft/Twente) по велошинам; Dell'Orto — другие статьи группы (relaxation length
2023, camber, скорость); мотоциклетные knobby-шины как ближайший прокси (Cossalter, Lot,
Sharp — данные off-road шин); данные производителей (Schwalbe/Continental белые книги).
Также: калибровочные практики — как получают `pressure_exponent` для боковых жёсткостей.

**Находка — это.** Полосы `C_α/F_z` [1/рад], `C_γ/F_z` [1/рад], `σ_y/σ_x`, показатели по
нагрузке и давлению с условиями, в формате `tyre_lateral_reference.json` spec §10.4
(включая провенанс по значению и статус `pinned/unpinned/disputed`).

**Зачем проекту.** Фаза p0 spatial-3d Task 2 — прямо.

### D. Multipass, колея и память грунта для лёгких машин (P2)

**Вопрос.** Насколько заднее колесо велосипеда выигрывает/проигрывает, идя по следу
переднего, на сыпучем материале, и какие простые модели multipass существуют?

**Искать.** Holm 1969 multipass, Senatore & Sandu, Wong (multipass in Theory of Ground
Vehicles), rover-литература (одноосные/двухосные следы), тракторная (tandem wheels, «rut
following»), модели уплотнения за проход (пропорция остаточной просадки, изменение `k`).
Отдельно: щебень vs песок — у крупного угловатого материала память иная (переупаковка).

**Находка — это.** Доля восстановления просадки между проходами; изменение `k_eq, n` после
прохода; оценка, меняет ли multipass исход сценария «подъём по сыпухе» для велосипеда с
базой 1.2 м (разница тяги заднего колеса, %). Решение «нужен ли уровень B».

**Зачем проекту.** Дизайн сыпухи §9 п.1, решение о колее в 3D-рельефе (`.terrain3d` как
сетка допускает деформацию).

### E. Алгоритмы деформируемого рельефа в реальном времени и их детерминизм (P2)

**Вопрос.** Как реализуют деформируемый грунт в реальном времени, с каким бюджетом и
какой воспроизводимостью, и что из этого переносимо на лучевую шину над сеткой высот?

**Искать.** SCM (Krenn & Hirzinger, DLR; Chrono SCM — внутреннее устройство: сетка,
bulldozing, erosion, активные домены); деформируемые heightfield в играх и симуляторах
(публикации по MudRunner/Spintires-подобным системам, Unreal/Unity terrain deformation,
«real-time terramechanics» GPU); AGX Dynamics / Vortex Studio terrain (белые книги);
Gazebo/Isaac deformable; NASA/JPL ROAMS; сельхоз-симуляторы. Фокус на (а) тонкий слой с
дном, (б) детерминизм (фиксированный порядок редукций, независимость от числа потоков),
(в) стоимость на шаг при 2 колёсах × 64–256 элементов.

**Находка — это.** Сравнительная таблица алгоритмов: состояние на ячейку, обновление за
шаг, стоимость, как решают multipass/bulldozing, воспроизводимость; что минимально нужно
для уровня B в этом проекте.

**Зачем проекту.** Уровень B, 3D-рельеф, master plan (bitwise invariance по потокам).

### F. Наезд пневматической шины на камень/ступень: измерения и модели (P1)

**Вопрос.** Какие есть измерения сил и деформаций MTB/вело/мото-шины при наезде на
препятствие (cleat, ступень, камень) — для проверки enveloping нашей лучевой модели и для
3D-случая «камень под плечом покрышки»?

**Искать.** Dressel & Sadauckas 2020 (есть ли obstacle/cleat tests), Sadauckas 2024
drop/impact (детали), cleat tests в автомобильной литературе (Zegelaar, Schmeitz SWIFT —
методика enveloping с cleat'ами, масштабируемо?), мотоциклетные испытания на ступенях,
исследования rim strike / casing damage (Schwalbe/ENDURO, tyre inserts), данные о
боковом наезде (камень под плечом → боковая сила и момент на руль).

**Находка — это.** Хотя бы один измеренный набор «сила–время при наезде на препятствие
известной геометрии» для велошины или масштабируемый автомобильный; оценки боковой силы
от асимметричного наезда; что из SWIFT-подхода (эффективная дорога) пригодится для 3D
с торовым лучевым гридом.

**Зачем проекту.** Тест-риги §9.5 spatial-3d, валидация enveloping без лаборатории.

### G. Грунтозацепы и протектор на сыпучем материале (P3)

**Вопрос.** Как блоки протектора (knobs) меняют тягу и сопротивление на рыхлом щебне по
сравнению с гладкой шиной, и есть ли простые поправки к `τ_max` / `K` Яноши для
«зацепов» (grousers)?

**Искать.** Сельхоз-литература по lug/grouser effect (Wong; Ding 2011 grousered wheels),
rover grousers, MTB-специфика (Dressel: knob effects на жёсткость; исследования knob
height vs traction), мотошины enduro.

**Находка — это.** Поправочный коэффициент/полоса для `tan φ_eff` или `τ_max` при высоте
зацепа 4–6 мм на материале с частицами 1–10 см; меняется ли `K`.

**Зачем проекту.** Дизайн сыпухи §4.3 (потолок сцепления), §9 п.2.

### H. Домашние и полевые измерения для калибровки сыпухи (P0)

**Вопрос.** Какие измерения можно сделать без лаборатории — весы, линейка, телефон с IMU,
велосипед, куча щебня, склон — чтобы получить `k_eq, n, φ, c`, Crr и предел тяги с
погрешностью, достаточной для полос §8?

**Искать.** Методики: bevameter и его DIY-варианты (пластинчатый тест с грузами), угол
естественного откоса как оценка `φ`, direct shear box упрощённый, coast-down для Crr с IMU
(протоколы из cycling science, ISO 28580 как ориентир по учёту ветра/уклона), тест
«буксование на месте» (измерить просадку за N оборотов). Опубликованные low-cost
террамеханические стенды (университетские курсовые, rover-клубы).

**Находка — это.** Протокол на 1–2 страницы на каждое измерение: что мерить, сколько
повторов, как считать параметр, ожидаемая погрешность, типичные ошибки. По образцу
Appendix A пневматического плана (две точки нагрузки на колесо).

**Зачем проекту.** План сыпухи, Appendix «измерения для пользователя».

### I. Детерминированные численные схемы для контактных/террамеханических законов (P3)

**Вопрос.** Какие практики обеспечивают побитовую воспроизводимость (между запусками,
компиляторами, числом потоков) для итеративных локальных решателей (бисекция/Ньютон с
фиксированным числом шагов) и редукций в физических движках, и какие подводные камни
известны (FMA, транцендентные функции, упорядочивание)?

**Искать.** Reproducible floating point (Demmel & Nguyen, ReproBLAS), практики игровых
движков с lockstep-детерминизмом (Rapier, Box2D deterministic builds), MuJoCo/ODE/Chrono
обсуждения детерминизма, `-ffp-contract`, libm-различия между платформами (sqrt — точно,
exp/tanh — нет), compensated/pairwise суммирование.

**Находка — это.** Чек-лист для `soft_layer` и 3D-редукций; какие функции в формулах
дизайна (sqrt, pow с нецелым `n`, tanh, exp) требуют собственной реализации или
табулирования для кросс-компиляторной побитовости.

**Зачем проекту.** Дизайн сыпухи §4.1 (бисекция, `z^n`), master plan (invariance).

### J. Что предполагают о шине и грунте реальные контроллеры тяги/anti-wheelie (P3)

**Вопрос.** Какие модели шины/грунта лежат в основе traction control и anti-wheelie у
e-MTB/мотоциклов (Bosch eMTB, Shimano, Specialized, Bosch Motorrad MSC, KTM/Husqvarna
traction control), какие сигналы они используют и что считают «рыхлой поверхностью»?

**Искать.** Патенты (Bosch eBike Systems: «Verfahren zur Traktionskontrolle», wheelie
detection; Yamaha/Shimano), конференции по мотоциклетной динамике (Bikes/Motorcycles
Dynamics Conf.), работы по оценке `μ` на ходу (μ-estimation, slip-slope), MTB-специфика
(crank-torque + wheel speed без датчика скорости переднего колеса).

**Находка — это.** Список предположений контроллеров о шине (линейная slip-slope, µ по
классам), какие эффекты сыпухи (просадка, R_c, slip–sinkage) они бы «увидели» как
аномалию — то есть что симуляция обязана воспроизводить, чтобы быть полезным стендом.

**Зачем проекту.** Цель проекта (§1 spatial-3d): релевантность эффектов к контроллеру.

### K. Физика осыпей как материала (P0)

**Вопрос.** Что известно о механике альпийской осыпи (talus/scree) как сыпучей среды:
гранулометрия, угол откоса, трение камень–камень, устойчивость тонкого слоя на склоне под
точечной нагрузкой (сдвиг слоя целиком), поведение под циклической нагрузкой?

**Искать.** Геоморфология и геотехника talus slopes (angle of repose 33–40°?, частицы,
сортировка по склону), rockfall/scree stability, «shallow granular layer on inclined
rigid base» (физика гранулярных сред: Pouliquen flow rule, h_stop(θ) — минимальная
толщина слоя, устойчивого на уклоне θ!), трение rock-on-rock (basalt/granite/limestone),
данные о проходимости осыпей (альпинистские/военные наставления дают качественные
категории).

**Находка — это.** Полосы `φ`, гранулометрии, трения камень–камень; критерий «слой
поедет целиком» как функция уклона и толщины (`h_stop`) — это отдельный режим отказа,
которого нет ни в одном шинном подходе и который на 25–35° подъёмах может быть главным.

**Зачем проекту.** Дизайн сыпухи §4.3/§8, новый возможный режим «сдвиг слоя» для 3D
на косогоре.

### L. Боковой уклон, развал и боковое вытеснение на рыхлом (P1)

**Вопрос.** Как колесо с развалом на рыхлом материале создаёт боковую силу (bulldozing
боковой стенкой, lateral sinkage), какие модели есть (Ishigami et al. для роверов,
мотоциклетные off-road), и насколько это важно при ±15° бокового уклона?

**Искать.** Ishigami 2007 (wheel-soil lateral), Krenn SCM bulldozing, мотоциклетные
knobby-шины под креном на гравии, rover slope traverse experiments (lateral slip on
slopes), MTB side-hill traversal (качественно).

**Находка — это.** Модель боковой силы на рыхлом в формате, совместимом с §10.3
spatial-3d (патч → `F_y`), полосы параметров; оценка важности при наших уклонах.

**Зачем проекту.** p3 pneumatic_3d, дизайн сыпухи §9 п.4.

### M. Переносимые open-source реализации террамеханики — глубокий разбор (P2)

**Вопрос.** В каких открытых проектах есть **читаемая, проверенная** реализация
Bekker/Janosi/Wong-Reece/SCM, какие численные решения там приняты (как ищут просадку, как
считают `j`, как обрабатывают дно/границы), и что из этого можно взять как референс для
тестов `soft_layer`?

**Искать.** Chrono `SCMTerrain` (CPU и GPU ветки), PINNeAPPle terramechanics, Gazebo
plugins, ROS-rover-симуляторы, Python-пакеты (terramechanics, `pyterramech`?), MATLAB
File Exchange (Wong-Reece калькуляторы), курсовые репозитории с валидацией по Wong Table
2.x; AGX Terrain (закрыт, но документация формул открыта). Для каждого — тесты: есть ли
проверка на известных табличных случаях.

**Находка — это.** 3–5 референсных реализаций с указанием функций (файл:строки), какие
численные задачи (`z^n`, интеграл работы, slip–sinkage) и как решены; «эталонные случаи»
с числами, на которых можно тестировать `soft_layer` (штамп известного размера → просадка).

**Зачем проекту.** Тесты §7 дизайна сыпухи — внешние эталонные случаи вместо только
самопроверок.

### N. Пределы применимости Беккера для малых штампов и крупных частиц (P2)

**Вопрос.** Справедлив ли континуальный закон давление–просадка, когда пятно 50×130 мм
давит на частицы 10–100 мм (отношение размеров ~1–5)? Какие есть поправки или
альтернативы (дискретные/статистические модели опоры на несколько камней)?

**Искать.** Scale effects in bevameter tests (размер штампа vs частицы), DEM-исследования
«small wheel on coarse gravel», модели «опора на N точках» (контакт с несколькими
камнями как случайный процесс — для нашей многолучевой шины естественнее!), работы по
шагающим роботам на щебне (Boston Dynamics/ETH ANYmal на осыпях — терраин-модели),
планетоходы на крупнообломочном грунте.

**Находка — это.** Критерий, когда щебень нужно моделировать как «набор камней на
жёстком» (то, что уже умеет лучевая шина + генератор рельефа с камнями), а когда — как
континуум Беккера; возможно, гибрид: континуум для мелкой фракции, явные камни для
крупной. Это может **изменить дизайн сыпухи целиком**, поэтому угол приоритетный внутри P2.

**Зачем проекту.** Дизайн сыпухи §1/§4 — проверка самой предпосылки; генератор рельефа
(размер и плотность камней как часть «сыпухи»).

## 4. Пакетирование для воркфлоу

- Один запуск = один угол + контекст-пакет §1 целиком. Не объединять углы: верификаторы
  теряют фокус.
- Бюджет источников на угол: 20–40 первичных; при исчерпании поисковой квоты — записать
  это в caveats, как сделал запуск 2026-10-13.
- Итог запуска класть в `.scratch/tire-research/<угол>/` (json + html + `findings-memory.md`
  по образцу существующего), затем свести в один аудит
  `docs/superpowers/audits/<date>-deep-research-round-2.md` с таблицей «что меняется в
  дизайне сыпухи / 3D / калибровке» по пунктам спецификаций.
- Стоп-критерии для всего раунда: закрыты P0 (A, B, H, K) с полосами параметров и хотя бы
  одним протоколом измерения; по C есть JSON-кандидат для `tyre_lateral_reference.json`;
  по N есть ответ «континуум / камни / гибрид».

## 5. Чего не делать

- Не рекомендовать FEA/DEM/XPBD как tick-path-модель — решено.
- Не пересобирать обзор Chrono/SymBRiM/yamazaki — есть в отчёте 2026-10-13.
- Не предлагать замену лучевой шины на Pacejka/Fiala/TMeasy.
- Не выдавать оцифрованные с графиков числа за измеренные; не усреднять полосы из разных
  условий в одно «рекомендуемое значение».
