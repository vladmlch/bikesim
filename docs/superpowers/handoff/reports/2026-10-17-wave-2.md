# Вторая волна portability: T19 и T24

Дата: 2026-10-17. Статус обеих задач: **implementation_ready**.
Проверки исполнения: **not_run_by_user_instruction**.

Реализация второй нумерованной волны завершена и прошла независимое
статическое ревью. Приложение, тесты, сборщики, компиляторы, installer,
GUI, platform probes и загрузка зависимостей не запускались. Тесты
написаны, но даже collection не выполнялся. Статус `verified` не выставлен.

распакованы 1110 исходных файлов. Экспорт уже содержит реализацию первой
волны T18/T20/T23 с непроведёнными execution gates; она служит входом для

## T19: запуск viewer и владение ресурсами

Сохранён ранний возврат `ensure_macos_mjpython()` на Linux и существующий
успешный macOS маршрут: один re-exec, исходные аргументы, `MUJOCO_MJPYTHON`
и обработка `DYLD_FALLBACK_LIBRARY_PATH`.

Исправлены конкретные проблемы, найденные чтением исходников:

- Отсутствующий `mjpython` выдаёт явную диагностику. Неудачный поиск или
  re-exec восстанавливает sentinel и прежнее окружение; повторная попытка
  не может обойти launcher из-за состояния неудачного первого вызова.
- В playground и legacy ride проверка launcher выполняется до импорта
  viewer. Удалена дублирующая инициализация async worker до launcher;
  существующая инициализация после него сохранена.
- В recorded playback Q/Escape выставляет запрос остановки. Окно
  закрывается владельцем render context; ранний callback не обращается
  к ещё не присвоенному window handle.
- Physical viewer и checked replay сохраняют первичную ошибку, если
  cleanup тоже завершается исключением. Самостоятельная ошибка cleanup
  остаётся ошибкой. Коды завершения replay сохранены.
- Создание и подключение research recording run находится внутри
  существующей границы cleanup; ошибка частичного setup больше её не обходит.

Изменения затрагивают шесть runtime-файлов: `sim/playground.py`,
`sim/ride/viewer.py`, `sim/ride/playback_viewer.py`,
`sim/ride/physical_frontend.py`, `sim/research/viewer.py`,
`sim/research/replay_viewer.py` внутри `src/bike_sim/`.

Добавлен `tests/portability/test_viewer_launch_platform.py`: платформенные
контроли launcher и владения ресурсами используют подставные окна.
Они не являются доказательством работы Cocoa, X11 или XWayland.

В `docs/development/viewer-platform-acceptance.md` записаны 15 pending-строк:
physical, research, checked replay, recorded playback и playground для
macOS, Linux X11 и отдельно Linux XWayland. Есть команды будущей проверки,
управление с клавиатуры, open/close и interrupt, terminal hold, requested
и achieved RTF. Физические периоды, numerical contracts, render snapshots
и политика opt-in recording не менялись.

Legacy `--view` по-прежнему восстанавливает собственную модель и вызывает
`mj_forward` для показа записанных поз. Его переносимость и cross-host
совместимость остаются работой T22, а запись и finalization — T21.

Подробности: [отчёт T19](2026-10-17-T19.md).

## T24: исходные offline bundles и точные зависимости

Добавлены `tools/offline_bundle.py`, `tools/offline_manifest.py`,
`tools/prepare_offline_tools.py`, `tools/check_offline_sources.py`,
`tools/make_offline_bundle.sh`, full/slim README и два файла тестов.

### Исходники и manifest

Schema 1 описывает источник, commit/dirty state, target OS/architecture,
Python/ABI и wheel tags, capabilities, lock/export hashes, wheel inventory,
source inventory, prerequisites и точные slim external providers.

Сборщик копирует текущие байты tracked-файлов с режимами доступа, плюс
явно разрешённые assets. Он исключает Git metadata, приватные настройки,
virtualenvs, caches, output/dist и сгенерированные native binaries.
Произвольно названные build/venv-каталоги определяются по маркерам.
Проверяется confinement исходного и разрешённого пути symlink. Настоящие
tests/fixtures не отбрасываются из-за имени каталога или расширения данных.

Перед публикацией повторно проверяются исходные байты, режимы, HEAD,
tracked status и index. Существующий результат не перезаписывается.
Native-режим проверяет обязательные CMake inputs и benchmark assets.

### Зависимости, full и slim

Предусмотрены проверка актуальности исходного lock и frozen export.
Колёса выбираются из точных URL/хешей `uv.lock`, сверяются с export и
проходят проверки SHA-256, tags, METADATA/WHEEL, Requires-Python,
extras и активных dependency edges. Source-only fallback отсутствует.

Отдельный supplemental tool lock строится из уже выбранных локальных
колёс uv, pip, setuptools, wheel и фактической backend/tool closure.
`prepare_offline_tools.py` читает байты и metadata без resolver,
скачивания или исполнения колёс; файл lock создаётся только по новому пути.
Включаются точные версии, хеши и evidence лицензии uv.

Full сохраняет весь closure. Slim сначала проверяет полный граф, затем
удаляет только явно выбранные колёса и записывает точные external versions
с профилем `pending-T25`. Отсутствующие колёса нельзя заново хешировать
по одному manifest: реальный import path, ABI и scientific provider на
получателе должен проверить T25.

Native target обязан совпадать с OS, architecture и Python автора bundle.
Старый Python-only маршрут выделен отдельно. При cross-target подготовке
target uv wheel не запускается на авторе; host build tools проверяются
по фактическим host tags, Requires-Python и host dependency markers.

`check_offline_sources.py` проверяет распакованный manifest bundle либо
отдельно сравнивает Python wheel с исходниками. `payload-consistent`
описывает целостность содержимого; native build и offline installation
такой результат не квалифицирует.

### Отсутствующие входы

В приложенном экспорте нет следующих обязательных исходных данных:

- Оригинального `uv.lock`.
- Независимого общего `tools/proto_native_bench/artifacts/model.mjb`.
- `model.mjb`, `state.bin`, `state.npz` выбранного через `current.json`
  versioned fixture. Присутствующий manifest не заменяет эти байты.
- Выбранного квалифицированного набора platform tool wheels с точными
  версиями и хешами для supplemental lock.
- Старых untracked offline scripts и `packaging/`.

Поэтому wrapper, checker и README созданы как новая реализация
документированного legacy-контракта. Это не импорт отсутствующего кода;
точное совпадение со старой невидимой реализацией не заявляется. Сохранены
описанные имена Linux x64 CPython 3.13 full/slim Python-only архивов.
Новые native source bundles требуют явного `--native`.

Production lock и бинарные assets не выдуманы и не сгенерированы.
До их восстановления реальная сборка bundle из этого экспорта должна
останавливаться на preflight. Installer остаётся задачей T25.

Подробности: [отчёт T24](2026-10-17-T24.md),
`packaging/OFFLINE_README_full.md`, `packaging/OFFLINE_README_slim.md`.

## Ревью и проверка результата

Реализация шла двумя потоками; третий участник выполнил независимое
статическое ревью. Исправлены найденные проблемы с host/target tools,
native assets и fingerprint, wheel identity и tags, source modes,
generated build trees, sidecar statuses и нестандартными объектами вместо
обязательных root files. Материальных замечаний к итоговым исходникам
при этом ревью не осталось.

## Передача изменений

Выдаются основной патч, точный Repomix-патч, ZIP изменённых файлов,
полный восстановленный source ZIP и этот отчёт. `_delivery/` в архивах
содержит патчи, инструкцию применения и per-file SHA-256 manifest.

Основной патч рассчитан на обычный checkout с завершающими переводами
строк. Вариант `-repomix.patch` рассчитан на точный результат распаковки,
где экспорт удалил последние переводы строк. Применять нужно один вариант.

```sh
git apply --check /absolute/path/bikesim-portability-wave-2.patch
git apply /absolute/path/bikesim-portability-wave-2.patch
```

Эти команды предназначены для пользователя. Здесь применение выполнялось
только к временным копиям файлов при подготовке патчей. Если в настоящем
checkout уже есть старые untracked offline scripts, сначала сопоставьте
их с новой реализацией: patch check не должен заменяться принудительной
перезаписью невидимых исходных файлов.

Source ZIP содержит восстановленные исходники, а не готовый offline
runtime distribution. Для следующего execution gate нужен настоящий
checkout с lock/assets и выбранными tools. Команды тестов, GUI и assembly
записаны в task reports и acceptance record; они не выполнялись в этой сессии.
