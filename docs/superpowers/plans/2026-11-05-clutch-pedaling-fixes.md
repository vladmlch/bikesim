# План: педалирование и мотор при муфте в моторе

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель.** Убрать ошибки, из-за которых при `motor_clutch = true` шатуны замирают. Ошибки найдены диагностикой
2026-11-05 (`.scratch/devin/2026-11-05-diag-clutch-stall/report.md` в основной копии). Затем включить муфту
(задача 3 плана `2026-11-05-motor-clutch.md`) и проверить езду (задача 4 того же плана).

**Почему.** При включённой муфте разгон по ровному даёт момент ног 7,3 Н·м вместо 21,9, мотор работает 34 % времени
вместо 94 %, наибольшая скорость 14,6 км/ч вместо 23,7. Цепочка такая: муфта размыкается, шатун отстаёт от вала,
педаль проворачивается вхолостую, ноги не дают силы, и мотор выключается. Части этой цепочки — ошибки кода, в
котором осталось «шатун = вал».

**Место работы.** Ветка `physics-2026-11-05`, рабочее дерево `.worktrees/physics-2026-11-05`, сборка
`build/native-release` уже есть. Включение муфты из задачи 3 лежит там незакоммиченным (5 файлов).

## Решения пользователя (2026-11-05)

- **Р1. Выбег мотора.** «Если райдер начинает давить слабее — мотор какое-то время держит прежнюю мощность, потом
  подстраивается под новую. Полная остановка кручения попадает в это подмножество: какое-то время мотор будет
  продолжать крутить, потом полностью остановится».
  - Новый ключ `[drive.assist] release_hold_s` — сколько мотор держит прежнюю мощность после ослабления нажима.
  - **Значение по умолчанию: 0,3 с, пометка «не проверено».** Пользователь подтвердил план и число 2026-11-05
    («да, нормально»). Параметры Bosch в интернете не искать (запрет пользователя).
  - Нарастание момента остаётся как сейчас: через сглаживание 40 мс.
- **Р2. Нога ускоряет педаль сама.** «В реальном педалировании нога обычно ускоряется сама собой: под весом, и
  ускорение педали не настолько быстрое, чтобы человек не успевал». Скорость шатуна для райдера — только верхняя
  граница («быстрее не кручу»), а не цель, к которой он тормозит шатун.
- **Р3. Переключение по одной звезде.** Каденс выше верхней границы полосы — на одну звезду тяжелее, ниже нижней —
  на одну легче. Если после паузы `shift_cooldown_s` каденс всё ещё вне полосы, переключение повторяется.
- **Р4. Тест приёмки** проверяет поведение каденса, а не число переключений. Порог «≥ 5 переключений» был способом
  бороться с замиранием и удаляется.

## Общие ограничения

- **Без подстройки.** Пределы, полосы каденса, фильтры, задержки, силы и пороги не меняются, кроме нового ключа из
  Р1. Если после задач 1–4 замирание остаётся, остановись и доложи числа.
- **Нет новых сил.** Мотор по-прежнему помогает не больше `gain·sensed·taper` в пределах ограничения
  («Действует», пункт 16). Выбег держит уже набранную мощность и не добавляет новой.
- **При жёсткой связи (`motor_clutch = false`) задачи 1, 2 и 4 поведения не меняют**, кроме выбега мотора и
  переключения. Задача 3 меняет езду и при жёсткой связи, это ожидаемо.
- **Эталонные записи** не перезаписываются: это делается один раз потом, в задаче 5 плана муфты. Узлы, которые
  падают только из-за устаревших записей, идут в список. Любое другое падение — настоящее.
- **Проверки.** Внутри задачи — `mise run test '<шаблон>'`. В конце задачи — проверки cppcheck, frontends и tidy на
  изменённых единицах трансляции (пока устаревшие записи падают, `check_change.sh` до них не доходит). Две
  проверки одновременно не запускать.
- **Коммиты:** одна задача — один коммит, в стиле `git log`, с `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

- **О1.** После задачи 1 мотор выдаёт момент при зажатом тормозе или когда сила ног ниже `engage_torque_nm` дольше
  `release_hold_s`.
