## 0. Главное в трёх абзацах (для нетехнического чтения)

Исследования подтвердили одно большое и несколько средних изменений. **Большое:** сыпуху
нельзя считать однородным «мягким ковром». Камни в ней (1–10 см) сравнимы по размеру с
пятном контакта покрышки (5×13 см), а для такого соотношения формулы «грунт как сплошная
среда» (Беккер) не работают — все три источника сходятся. Правильная картина — **камни как
явные выступы рельефа** (это ваша многолучевая шина уже умеет), а мягкая «матрица» из мелочи
между ними — только там работает Беккер. Значит, сыпуха — это наполовину задача *генератора
рельефа*, наполовину — шины.

**Средние:** боковые характеристики MTB-шин при низком давлении *измерены* (Sadauckas &
Dressel 2020) — но два отчёта извлекли из одной статьи числа, различающиеся в 1.5–2 раза,
поэтому брать надо не чьи-то числа, а оцифровать статью самим. Таблица трения поверхностей
оказалась автомобильной (Буркхардт) — нужна семья поверхностей «скала». Генератор трассы
во многом ошибается по форме: уклон «дышит» короткими отрезками 4–8 м, а не рампами 15–30 м;
сыпуха идёт длинными траверсами, а не кусками 6–15 м внутри рампы; на 26–32 % по сыпухе
тяги физически нет — стенки должны быть на твёрдом; шероховатость — степенной спектр, а не
гауссово сглаживание. Для 3D-рельефа: «боковой уклон ±15°» смешивает два разных параметра
(уклон местности и поперечный уклон полотна), нужна ширина полотна и обязательны шпильки.

**Что это значит для порядка работ:** сначала короткая волна **проверок спорных чисел**
(потому что внешние отчёты расходятся с аудитами в нескольких местах более чем вдвое), затем
правки **спецификаций**, затем параллельная реализация на Python (генератор, данные,
поверхности) и на C++ (численный фундамент, затем слой сыпухи). 3D-фазы p0–p8 продолжаются
по своим планам с поправками спецификации.

Внешние отчёты дали и то, чего в аудитах нет и что принимается без спора: двуосевые пресеты
`uphill_class × obstacle_class` (ChatGPT), метаданные `provenance/confidence` на поле
генератора (ChatGPT), примитив `rock_slab` 0.8–2.0 м и бимодальное боковое размещение камней
(Gemini), тест drop-sled по Sadauckas 2024 с числами (Gemini), тест «инверсия давления»
(снижение давления 2.0→1.3 бар должно снизить сопротивление на рыхлом на 8–15 % — Gemini;
ChatGPT считает тренд не установленным → тест пишется, но помечен `disputed`).

Найденная арифметическая ошибка во внешнем отчёте: золотой случай Gemini TC-M1 (`R_c = 27.00 Н`)
не следует из его же формулы (пересчёт даёт ≈ 20.0 Н) — внешние «golden cases» не брать без
пересчёта.

## 6. Правила для агентов (вставлять в каждое задание)

1. **Один WP — один агент — одна ветка** `feat/r2-<wp>` от свежего `main`. Коммиты по задачам
   WP, сообщение `<type>: <summary>`.
2. **Владение файлами.** Менять только файлы из списка «владеет». Если для задачи нужно
   тронуть чужой файл — остановиться и написать в hand-back, что и зачем; не делать.
3. **Байты планарного режима священны** (master plan spatial-3d): любой существующий пресет,
   TOML, golden, `test_native_*` — побитово. Новое поведение — новые имена
   (`scree_soft`, `AlpineGenSpecV2`, `DrainDip`), старые не переопределяются.
4. **Провенанс на каждое число.** Любая константа в коде или спеке несёт источник и пометку
   `measured/digitised/standard/authored/extrapolated/disputed`. Числа из внешних отчётов
   (`docs/researches/`) без первоисточника — только `authored`.
5. **Тесты по AGENTS.md:** `quick` для Python вне нативной области, `native` для всего, что
   касается `native/`, биндингов, проекции конфига; `full` для физики/реалтайма. Нативные
   ядра: `noexcept BIKE_NONBLOCKING`, без аллокаций, фиксированный порядок редукций,
   `-ffp-contract=off`, RTSan/ASan.
6. **Hand-back** — короткий отчёт: что сделано, какие гейты зелёные (команды и итог), что не
   удалось, какие вопросы вверх. Для WP с числами — таблица «было/стало/источник».
7. **Не расширять скоуп.** Соседняя находка → строка в hand-back, не правка.
8. Пояснительный тон в документах: термины раскрыты при первом употреблении (читатель
   проекта — не специалист по симуляции).
