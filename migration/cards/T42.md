## F101: `src/bike_sim/recording/interrupt.py`

**Source:** lines 1-64; SHA-256 `17ab7536f457aa3599c18902a6fefb0bc2124fd73c1fe394b5ce614875e5301c`. **Owner:** T42; **deletion:** T63 after row evidence.

**Source module purpose:** Deferred-SIGINT shield for evidence-critical publication sections (R04). Seal+finalize is a critical section: a second Ctrl-C delivered mid-write can strand journaled input events against an unsealed episode or corrupt the staged publication — the launch then loses its entire owned recording. On the main thread, ``InterruptShield`` swaps the SIGINT handler for a flag-setting one for the scope of its ``with`` block, so an interrupt is recorded in ``deferred`` and honored after the section completes instead of interrupting the write. ``signal.signal`` cannot install handlers off the main thread; there the shield degrades to a flag holder, and ``note()`` is the injected-hook seam a caller (or a test without access to real signal delivery) uses to record a deferred interrupt.

**Source:** lines 1-289; SHA-256 `5d00e508a62c5ebc4fa23f1553bfb5dc89ba8a4b0dc9d9e8505ef974ec570f0c`. **Owner:** T42; **deletion:** T63 after row evidence.

**Source module purpose:** Off-path period publication: a spawned process evaluates closes. PhysicalRuntime accumulates RawStep payloads for one control period, then publishes them through publish_close — pure data work (attachment wrenches, effort channels, ledger bookkeeping, sample assembly) that never touches live mjData. That makes it movable: this module runs the same publish_close inside a spawned worker, so the stepping loop only serializes raws and applies results at the next step boundary. Semantics: identical code on identical data, applied one step later. Runs where nothing consumes mid-period published state for control decisions are bitwise identical to synchronous runs; the interactive viewer is such a consumer-free path. Policy sessions that read ``physical.sample`` to act may observe one-period-older observations under a slow worker.
