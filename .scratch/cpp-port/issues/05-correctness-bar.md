# Планка корректности: что считается «та же симуляция»

Type: grilling
Status: resolved
Blocked by: —

## Question

Что является критерием «порт верен»? Варианты планки: побитовая эквивалентность траекторий (нереалистично через разные решатели/BLAS?) / допуски на траектории qpos/qvel / эквивалентность производных метрик (энергия, контактные силы, метрики езды) / статистическая эквивалентность на эпизодах. Какие референс-артефакты фиксируем: golden trajectories, episode metrics, per-step oracle из текущего пошагового кода? Как это соотносится с существующим `tests/reference/` — Python-версия остаётся оракулом или нет?

## Answer

**Решение: слоистая планка, оракул через артефакты, bespoke — ослабленная планка.**

### Слои эквивалентности (MuJoCo-формы: гибрид, полный порт)

1. **Per-call идентичность математики.** Те же входы → те же выходы до ~1e-12 (rtol+atol) на портируемых функциях: писатели сил, телеметрия связей, энергоучёт, контроллер, QP. Бит-в-бит не требуется (другой порядок FP-операций легален), но в гибридной форме шов переносит double'ы без изменений — там побитовость достижима и полезна как диагностика «шов чист».
2. **Детерминированная эквивалентность эпизода в пределах горизонта расхождения.** Проверяется на записываемой поверхности: все каналы рекордера совпадают в допусках на канал; отчёт нарушений бюджетов — тот же первый нарушающий шаг и те же строки нарушений; сырое состояние (qpos/qvel/qacc per step) в допусках. Горизонт измеряется perturbation-тестом: референс + возмущение 1e-14 → шаг, где траектории расходятся выше допусков. Порт обязан держать слой 2 не короче этого горизонта; расходиться раньше = fail.
   - Допуски на канал выводятся из разброса самого референса (perturbation-ансамбль), не назначаются руками.
   - Эквивалентность — на записываемой/наблюдаемой поверхности (контракт рекордера + отчёт нарушений), не на внутреннем per-step счёте: порт волен считать лениво/батчем (паттерн P-плана), лишь бы публикуемое совпадало.
3. **За горизонтом — статистическая эквивалентность.** Распределения производных метрик (энергоучёт, ride-метрики, acceptance-векторы) на ансамбле сценариев/сидов, не pointwise-сравнение траекторий.

### Оракул

Python-версия — оракул **через записанные артефакты**, не живой: референс фиксируется golden-эпизодами; Python нужен только для их (пере)генерации. Живое side-by-side сравнение не требуется ни на одной проверке.

### Референс-артефакты

Per-step qpos/qvel/qacc + весь контракт каналов рекордера (~100 колонок) + отчёт нарушений бюджетов — для канонических сценариев. Предлагаемый набор (уточняется при записи): дефолтный welded/spindle-профиль на 2–3 трассах разной контактной нагруженности; legacy-ветка с QP (weld или flat-pedal) — покрывает другой код-путь контроллера; sphere-tyre конфиг — штатный контакт MuJoCo вместо custom tyre; сценарий с нарушением бюджета — семантика «первый нарушающий шаг». Требование при записи: сценарии детерминированы — повторный прогон Python даёт бит-стабильные артефакты (проверяется при снятии референса).

### Bespoke-форма (свой движок)

Планка ослаблена: слои 1–2 недостижимы в принципе (другой решатель → другие силы даже per-step). Bespoke «верен» = статистическая эквивалентность метрик (слой 3) + качественные инварианты (энергобаланс, нарушения бюджетов). **Отсутствие траекторной проверки — зафиксированный минус bespoke в ledger**: единственная форма без детерминированной защиты от регрессий физики.

### Следствия для карты

- «Абсолютный пол» из «Анатомии времени шага» (~5–6×) подтверждён недостижимым: контракт каналов обязателен — считать можно лениво, публиковать обязан всё.
- Гибрид получает бонус проверяемости: оркестрация та же → слой 2 держится и на длинных эпизодах.
- Запись самих артефактов — исполнительная работа после решения, не билет карты.
