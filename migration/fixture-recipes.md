## RCP-07: Validation/performance/GUI

Run source validation rigs using their existing profiles and record thresholds/results as evidence. A known failing reference scenario is a failing/diagnostic fixture, not a success fixture waiting to be fixed by new code. Port the gate unchanged unless an explicit physics change is separately approved.

Capture startup/model/equilibrium/stepping/recording-finalization timings on the actual supported machine with warmups/repetitions, input hashes, provider identity and valid completed duration. Performance remains unqualified until the same native workload is measured; no speed target is invented here.

For UI capture semantic HUD rows, control mapping, fake-clock pacing and initial/terminal/reset frames. Pixel baselines are separate from numerical state. Keep genuine display/HiDPI/manual checks explicit rather than pretending a headless test validates window behavior.

## Fixture review gate

For every path referenced by a task, the fixture ledger must identify its source recipe and factory/command, actual produced files, expected outcome, comparison class and hashes. A missing fixture is an acquisition failure. A fixture generated after the rewrite without reference evidence is not a valid legacy oracle. Keep baseline capture separate from ordinary test execution and prohibit automatic golden updates in the normal test runner.
