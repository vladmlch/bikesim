# Мягкая сыпуха: квазистатический деформируемый слой под `pneumatic`-шиной — design

Дата: 2026-10-14. Ветка (будущая): `feat/soft-scree`. Статус: черновик после аудита
`docs/superpowers/audits/2026-10-14-tire-research-vs-implementation.md`; три исходных
решения (тонкий слой над скалой; реализация только на C++; отдельная фаза вне графа
spatial-3d) подтверждены пользователем 2026-10-14. **Ждёт ревью файла.** Исполнение — по
плану, который будет написан после ревью.

Стиль: пояснительный. Каждый термин раскрыт там, где впервые нужен, потому что
читатель не обязан знать террамеханику.

## 1. Цель

Сейчас поверхность `scree` (`terrain/surface.py:110`) — это **жёсткая** дорога с пониженным
трением (`μ 0.45/0.38`) и бугристостью 1–2 см. Колесо в неё не проседает и не гребёт.
Реальная сыпуха делает три вещи, которых у модели нет: (1) проседает под колесом, и колесо
постоянно едет «из собственной ямки» — это сопротивление, которого нет на твёрдой дороге;
(2) при буксовании щебень уходит назад и колесо зарывается глубже; (3) предел сцепления
определяется не трением «резина–камень», а прочностью на сдвиг самого щебня, и зависит от
нагрузки иначе, чем кулоновское трение.

Цель — дать нативному `pneumatic`-бэкенду поверхность `scree_soft`, которая воспроизводит
эти три эффекта в **правильном знаке и порядке величины**, с энергоучётом, телеметрией и
тестами-инвариантами, не меняя ни байта в существующих прогонах.

Не цель: валидированная модель (измерений MTB на сыпухе нет — см. аудит §5), колея и
память грунта (уровень B), боковое вытеснение и 3D-тор (после p3 spatial-3d), Python-двойник.

## 2. Решения

| Ветвь | Решение |
|---|---|
| Физическая картина | **Тонкий слой** подвижного щебня толщиной `H_s` поверх жёсткой породы. Профиль трассы `h(x)` — **верх слоя** (то, что видно и что рендерится); скала на `h(x) − H_s`. Просадка ограничена `H_s`; дальше — обычная жёсткая дорога |
| Уровень модели | **A, квазистатический**: грунт не помнит прошлое, каждый шаг «восстанавливается». Колея и multipass — не в этом дизайне (уровень B, отдельное решение после измерений §8) |
| Где считается | Только C++ (`native/src/pneumatic/soft_layer.{hpp,cpp}` + точки встраивания в `PneumaticTyreModel`). Python-бэкенд `pneumatic` **отвергает** мягкие поверхности явно (`ValueError`), а не игнорирует |
| Корректность | Без Python-оракула, по схеме ADR 0002: unit/property-тесты, инварианты (энергия, монотонность, пределы), self-golden sha256-манифест, планарные bitwise-гейты для всех старых поверхностей |
| Байты планарного режима | Мягкий путь активен **только** если `H_s > 0` на поверхности луча. Для всех существующих поверхностей код не выполняется ни одной плавающей операцией — существующие golden-тесты остаются побитовыми |
| Где в шине | Пред-проход между пересечением лучей и каркасом: по каждому лучу общий «подход» `δ_tot` делится на сжатие шины `δ_t` и просадку грунта `z` (§4.1). Каркас (`carcass.cpp`) **не меняется** — он получает `δ_t` вместо `δ_tot` |
| Сцепление | Щётка не меняется; меняется её **потолок**: на мягкой поверхности предел касательного напряжения элемента = `min(μ_резина(V_s)·σ, c + σ·tan φ)` (§4.3). При `c = 0` это постоянный коэффициент `tan φ` — вырождается в то, что есть |
| Сопротивление | Сила уплотнения `R_c` на патч против направления движения (§4.2) и slip–sinkage (§4.4) с задержкой в один шаг по проскальзыванию патча |
| Конфиг | `SurfaceSpec` получает необязательную под-таблицу `soft` (§5). Нет таблицы — жёсткая дорога, как сейчас. Схема конфига не меняется (поле необязательное, с валидацией) |
| Поверхность | Новая `scree_soft` в реестре; старая `scree` остаётся байт-в-байт |
| Гейты | Все `tests/reference/test_native_*.py` зелёные; RTSan/ASan; два компилятора; `fast` на `alpine_scree` с `scree_soft` ≥ 1× в вьюере (как у всех шинных работ); энергия замыкается |

## 3. Факты, на которые опирается дизайн

- Каркас считает силу элемента из его сжатия `δ` (`carcass.py:236-249`, `carcass.cpp` —
  `evaluate_carcass_into(ring, delta_m, …)`): упругая часть на единицу дуги
  `f_e/Δs = c_A·p·w(δ) + k_c·δ`, где `w(δ) = 2√(δ(2ρ−δ))` — хорда сечения, насыщается на `W_c`.
  Это та формула, через которую делится подход (§4.1).
- Лучи дают `δ_tot = max(0, R − r_i)` от первого видимого пересечения с полилинией
  (`geometry.py::intersect`, `native/src/pneumatic/geometry.cpp`). Профиль — верх слоя.
- `SurfaceMap.at(x)` даёт поверхность в точке (`terrain/surface.py:201`,
  `nativecfg::SurfaceMap` в `config_types.hpp:241`); в C++ спецификация поверхности —
  `SurfaceSpec{name, mu_peak, mu_slide, slip_stiffness_per_load, stribeck_speed_mps}`
  (`config_types.hpp:228`). Карта приезжает по проводу `tire.surface_map` (`config.hpp:181`).
- Щётка клипует щетинку на `±μ·f_j` (детализированный ярус) или ограничивает патч `μ·N_p`
  (сосредоточенный; `brush.py:135-145`). Потолок — единственное место, где грунт входит в
  сцепление.
- Энергоучёт: тепловые потери патча уже считаются (`rolling_loss_w`, `slip_loss_w`,
  `model.py:359-361`); новая мощность грунта добавляется туда же.
- Энергоинварианты и allocation-free тёплое ядро — `docs/agents/native-engineering.md`;
  детерминизм и фиксированный порядок редукций — master plan spatial-3d (применимо и здесь).
- Сыпуха на треке: три секции по 7–9 м на `alpine_scree` (`examples/research/alpine_scree.toml`).

## 4. Модель

### 4.1 Разделение подхода: сколько сжалась шина, сколько просел грунт

Пояснение. Луч видит, что твёрдый обод колеса оказался на `δ_tot` ниже верха слоя. Часть
этого — сжалась покрышка (`δ_t`), часть — продавился щебень (`z`): `δ_tot = δ_t + z`. Две
«пружины» последовательно, сила в них одна и та же. Для шины сила известна (каркас), для
грунта берём классический закон **давление–просадка Беккера**: давление под штампом растёт
как степень просадки,

`p_soil(z) = k_eq · z^n`, `n ∈ [0.5, 1.5]`, `k_eq` [Па/мⁿ].

(У Беккера `k_eq = k_c/b + k_φ` зависит от ширины штампа `b`; здесь `k_eq` — один авторский
параметр поверхности на ширину MTB-пятна, чтобы не множить сущности без данных.)

Площадь, через которую элемент давит на грунт — его дуга `Δs` × хорда `w(δ_t)` (та же ширина,
что в пневматическом члене). Баланс сил на единицу дуги:

`c_A·p·w(δ_t) + k_c·δ_t = k_eq·z^n·w(δ_t)`, `δ_t = δ_tot − z`, `0 ≤ z ≤ min(δ_tot, H_s)`.

Левая часть убывает по `z`, правая растёт → корень единственный. Решается **бисекцией с
фиксированным числом итераций** (`kSoftSplitIterations = 32`, невязка < 1e-10 м на диапазоне
≤ 0.1 м) — фиксированное число, а не критерий останова, чтобы байты не зависели от данных
через ветвление. Если корень на верхней границе `z = H_s` — колесо дошло до скалы: `δ_t =
δ_tot − H_s`, остаток несёт порода (жёсткий контакт, как сейчас). Флаг `bedrock` на элемент.

Крайние случаи: `H_s = 0` → путь не выполняется (не «z = 0», а именно пропуск — гарантия
байтов). `k_eq → ∞` → `z → 0`, `δ_t → δ_tot`: тест проверяет сходимость к жёсткому
результату до 1e-9 отн. (не побитово — бисекция оставляет остаток).

Память каркаса (Maxwell, гистерезис, обод) считается дальше на `δ_t`, как и сейчас. Это
осознанное упрощение: вязкоупругость грунта не моделируется.

### 4.2 Сопротивление уплотнения

Пояснение. Чтобы продавить щебень на `z`, колесо совершает работу; при качении эту работу
приходится делать заново на каждом метре — получается сила, тормозящая движение, даже без
проскальзывания. По Беккеру работа на единицу ширины `∫₀ᶻ p dz = k_eq·z^{n+1}/(n+1)`.

На патч `P`: `R_c,P = Σ_{i∈P} w(δ_t,i) · k_eq · z_i^{n+1}/(n+1) · (Δs_i / L_P)`, где деление на
длину патча `L_P` переводит «работу на элемент» в силу на единицу пройденного пути (при
стационарном качении патч длиной `L_P` «переваривает» все свои элементы за `L_P` пути).
Направлена вдоль касательной патча против `sign(V_x)`, сужается через ноль скорости тем же
`tanh`-тейпером, что `tread_loss_force` (`model.py:471-482`), чтобы стоящее колесо не
получало силу.

Мощность `P_c = R_c·|V_x| ≥ 0` — в `rolling_loss_w` патча (новый слагаемый, отдельный
телеметрический канал).

На скале (`bedrock`) формула та же с `z = H_s` — слой под колесом продавлен полностью, но
впереди всё равно свежий; это даёт постоянное сопротивление на тонком слое, что и
наблюдается.

### 4.3 Потолок сцепления из прочности грунта

Пояснение. На асфальте предел тяги — трение резины: `μ·N`. На щебне раньше резины «ломается»
сам щебень: камни сдвигаются друг по другу. Прочность на сдвиг сыпучего материала —
закон Мора–Кулона: `τ_max = c + σ·tan φ`, где `σ` — нормальное давление, `φ` — угол
внутреннего трения (у сухого гравия 35–45°), `c` — сцепление (у сухого щебня ≈ 0).

На элемент `i` мягкой поверхности: `σ_i = f_i / (Δs_i·w(δ_t,i))`, потолок касательной силы
`t_max,i = min(μ_резина(V_s), c/σ_i + tan φ) · f_i`. Щётка (оба яруса) клипует на `t_max,i`
вместо `μ·f_i`; для сосредоточенной щётки потолок патча — сумма потолков элементов.
При `c = 0` второй член — константа `tan φ`, и `min` просто выбирает меньшее из двух
постоянных чисел: модель вырождается в текущую с другим `μ`. Поэтому новый параметр не
«дублирует» `mu_peak`: при `c > 0` появляется зависимость от нагрузки (лёгкое колесо держит
относительно лучше), а `mu_peak/mu_slide` остаются потолком резины.

Профиль сдвига по пятну (Яноши `τ = τ_max(1−e^{−j/K})`) **не вводится**: детализированная
щётка уже переносит накопленный сдвиг `j` щетинками, а `K` в ней — обратная жёсткость
протектора. Это упрощение записано как известная неточность (§9).

### 4.4 Slip–sinkage

Пояснение. Буксующее колесо выбрасывает щебень назад и садится глубже — потом тащит
больше. Самый простой эмпирический вид: эффективная толщина, доступная просадке,
растёт с проскальзыванием, то есть грунт под буксующим колесом «мягче»:

`k_eq,eff = k_eq / (1 + g_s·|κ'_P|)`, `g_s ≥ 0` (авторский), `κ'_P` — переходное
проскальзывание патча **с предыдущего шага** (одношаговая задержка исключает неявную
связку «грунт ↔ щётка» внутри шага и сохраняет фиксированный порядок вычислений).
При `g_s = 0` эффекта нет.

Петля положительной обратной связи (глубже → больше `R_c` → больше буксование → глубже)
ограничена сверху дном `H_s` — поэтому тонкий слой и выбран первым: у модели есть
естественный предел зарывания.

### 4.5 Что остаётся как есть

Каркас, щётка, релаксация, гистерезис, обод, тейпер нулевой скорости, нумерация патчей,
`qfrc`-отображение через `mj_jac` в центроиде. Патч-центроид и нормаль — из точек
пересечения с **верхом слоя** (координата просадки в нормаль не входит: при `z ≤ H_s ≪ R`
поправка нормали ниже уровня шума профиля).

## 5. Конфигурация

`SurfaceSpec` (Python и `nativecfg::SurfaceSpec`) получает необязательное поле
`soft: SoftLayerSpec | None`:

```toml
# внутри реестра поверхностей / TOML трека, пример
[soft]
layer_thickness_m   = 0.06    # H_s; 0 запрещён (тогда не задавать таблицу)
bekker_k_eq_pa_m_n  = 2.0e6   # k_eq; валидация: > 0
bekker_n            = 1.0     # n;  [0.5, 1.5]
friction_angle_deg  = 38.0    # φ;  (0, 60)
cohesion_pa         = 0.0     # c;  ≥ 0
slip_sinkage_gain   = 1.0     # g_s; ≥ 0
provenance          = "authored: Wong 2008 dry-sand/gravel bands, not measured"
```

Правила: таблица либо полная, либо отсутствует; `provenance` обязателен и непустой (как у
`TireSpec`); `scree_soft` в реестре = `scree` + эта таблица с авторскими значениями §8.
Провод `tire.surface_map.*.surface` получает ключи `soft.*` как **необязательные**
(`config.hpp:181-187`), `wire::keys` расширяется; отсутствие = `std::nullopt`.

Запреты (проверяются на setup, с полным путём поля в сообщении):

- бэкенды `compliant_2d`, `distributed_2d_reference` + карта с мягкой поверхностью → отказ
  (`tires.backend`), они не умеют;
- Python-бэкенд `pneumatic` + мягкая поверхность → `ValueError('soft surfaces are
  native-only')` в `PneumaticTireForceApplier.__init__`;
- `tires.surface_mode = "configured"` с мягкой поверхностью — разрешён (одна поверхность
  на весь трек), нужно для стендов.

## 6. Нативная реализация

- `native/src/pneumatic/soft_layer.hpp/.cpp` — чистые функции без состояния:
  `split_approach(delta_tot, tyre, soil, k_eq_eff) → {delta_t, z, bedrock}`,
  `compaction_force_per_arc(z, w, soil)`, `shear_cap_ratio(sigma, soil)`. `noexcept
  BIKE_NONBLOCKING`, без аллокаций, без ветвления по данным кроме детерминированных
  границ.
- `PneumaticTyreModel::evaluate_into`: после `intersect` и до `evaluate_carcass_into` —
  проход по лучам с мягкой поверхностью (`surface_map.at(x_i).soft`), запись `δ_t` в буфер
  `delta_m`, `z_i`/`bedrock_i` — в новый скретч `SoftScratch` размером `n_rays`
  (конструкция). После патчей — `R_c,P`, потолки щётки, мощность.
- Состояние: **нет** нового состояния шины (квазистатика). `κ'_P` предыдущего шага уже
  хранится (`PatchBrushState`). Значит state wire и `assign()`/rollback не меняются —
  это главный выигрыш уровня A для нативной дисциплины.
- Телеметрия (новые каналы, `recording/catalog.py`, на колесо): `soil.sinkage_max_m`,
  `soil.sinkage_mean_m`, `soil.compaction_force_n`, `soil.compaction_power_w`,
  `soil.bedrock_ray_count`, `soil.shear_capped_ray_count`. На жёстких поверхностях — 0/NaN
  по правилам каталога.
- Порядок суммирования — существующий pairwise-kernel в порядке лучей.

## 8. Калибровка: откуда числа

Измерений «MTB-покрышка на альпийской сыпухе» не существует (аудит §3 F7, отчёт deep-research
2026-10-13). Поэтому все значения `scree_soft` **авторские**, оформлены полосами, и тесты
проверяют полосы, не точки:

| Параметр | Полоса | Основание |
|---|---|---|
| `H_s` | 0.03–0.10 м | геометрия тонкого слоя над породой (решение пользователя) |
| `k_eq` | 1–5 МПа/м при `n = 1` | порядок Беккера для сухого песка/гравия (Wong, *Theory of Ground Vehicles*, таблицы параметров грунтов), пересчитанный на ширину пятна ~50 мм; при 150 кПа давления даёт `z` 3–15 см → с `H_s` упирается в дно под полной нагрузкой — ожидаемо для тонкого слоя |
| `n` | 0.8–1.2 | там же |
| `φ` | 35–42° | сухой угловатый щебень (угол естественного откоса осыпи ≈ 35–40°) |
| `c` | 0–0.5 кПа | сухой материал без связности |
| `g_s` | 0.5–2 | авторский; калибруется по качественному стенду §7 |

Что можно проверить без лаборатории: порядок величины сопротивления качению на рыхлом
гравии. Задача плана: найти опубликованные Crr велосипеда на гравии/щебне (ожидание
0.02–0.04 против 0.011 на асфальте — это ожидание, **не источник**; если источника не
найдётся, строка остаётся авторской). Стенд: прямая на `scree_soft`, 20 км/ч, 490.5 Н,
`Crr_eff = (R_c + гистерезис)/N`.

Реальное измерение, которое закрыло бы вопрос дёшево: наезд на стенде-качелях или просто
«опустить гружёный велосипед на кучу щебня и измерить просадку» — две точки нагрузки дают
`k_eq` и `n`. Записать в план как Appendix по образцу пневматического плана.

## 9. Известные неточности уровня A

1. Грунт без памяти: заднее колесо не видит след переднего; нет уплотнения повторным
   проходом. Направление B.
2. Нет профиля сдвига Яноши отдельно от щётки; `K` грунта не параметр.
3. Нормаль патча от верха слоя, не от продавленной поверхности.
4. Нет бокового вытеснения и бульдозинга стенок (станет важно на косогоре в 3D).
5. Вязкоупругость грунта (скоростная зависимость `k_eq`) отсутствует.
6. Все числа авторские (§8).
