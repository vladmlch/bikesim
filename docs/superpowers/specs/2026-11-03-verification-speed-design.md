# Быстрая и полезная проверка: решения

Дата: 2026-11-03. Ветка: `main3`. Решения согласованы с владельцем проекта в
разговоре 2026-11-03 (опрос по дереву решений). План работ:
[docs/superpowers/plans/2026-11-03-verification-speed.md](../plans/2026-11-03-verification-speed.md).

## Что измерено (на `main3`, 2026-11-03)

Источник — журналы `build/native-release/native_check_logs/<вид>/<прогон>/`
(время первого и последнего файла журнала) и `Testing/Temporary/CTestCostData.txt`.
Цифры совпадают на 6–8 прогонах подряд, то есть это не следствие одновременной
нагрузки.

| Стадия | Время | Сколько запусков программ |
|---|---|---|
| frontends (GCC) | 8–9 мин | 511 |
| tidy (clang-tidy) | 32–35 мин | 511 |
| analyzer (clang --analyze, основная + экспериментальная половина) | 59–60 мин, из них экспериментальная половина ~34 мин | 1022 |
| cppcheck | ~1 мин | 511 |
| odr | 19 мин | 512 |
| headers | 15–16 мин | 2380 (из них разных условий компиляции 751) |
| context, scripts, diagnostic-controls | меньше минуты | — |
| обычные тесты (CTest без `slow|package`, 183 теста, `-j8`) | ~1 мин | — |
| медленные тесты (`slow`, 49 тестов, по очереди) | ~46 мин, из них `coupled_rider_task` 27,5 мин и `native_coupled_rider_task` 10 мин | — |

Итого проходы анализа идут ~137 мин строго по очереди, на одном ядре из 16.
`AGENTS.md` называет «~15–30 мин».

Сессия 756fe4c4 (2026-11-03) запускала полную проверку 6 раз. Каждый раз она
заново проходила уже прошедшие стадии. Пятый прогон шёл 2 ч 21 мин и упал на
двух обычных тестах, каждый из которых падает меньше чем за 5 с.

Экспериментальная половина анализатора за прогон выдаёт ~4 650 предупреждений
в 453 из 511 файлов и никогда не останавливает проверку.

## Решения

1. **Границы времени.** Проверка одного изменения — не больше 5 мин. Полная
   проверка на свободной машине — не больше 30 мин. Если не укладываемся,
   ускоряем саму проверку, а не выкидываем её части без замера.
2. **Три уровня.**
   - Уровень 1 «своё изменение»: сборка, обычные тесты, `cppcheck`, проход GCC
     и `clang-tidy` только для изменённых файлов и файлов, подключающих
     изменённые заголовки. Запускается после каждой правки.
   - Уровень 2 «полная»: всё как сейчас в `native`. Ровно один раз перед
     слиянием в главную ветку, не в каждой задаче и не в каждой параллельной
     ветке.
   - Уровень 3 «расширенная»: полная плюс медленные тесты. Раз в сутки или
     перед крупным слиянием.
   - Linux не входит ни в один уровень: его тесты запускаются отдельно и только
     по явной просьбе.
3. **Два теста, которые падают без всяких изменений**, чиним. Если что-то не
   удаётся починить быстро — временно отключаем с пометкой, причиной и задачей
   на починку. Списка «разрешённых падений» не заводим.
4. **Очереди нет.** Одновременные проверки не ждут друг друга. Каждая берёт долю
   ядер по числу уже идущих проверок и пишет в выводе, что рядом идёт другая.
5. **Порядок стадий** — от дешёвого к дорогому, обычные тесты в самом начале.
   Набор проверок не меняется.
6. **Продолжение с упавшей стадии** разрешено при промежуточных повторах после
   исправлений. Итоговое подтверждение перед слиянием — всегда полный прогон с
   начала.
7. **Экспериментальная половина анализатора** убирается из всех уровней.
8. **Отдельный проход анализатора** сначала сравниваем по находкам с
   `clang-tidy`, у которого включены те же проверки `clang-analyzer-*`. Решение
   о его судьбе принимается после замера, не в этом плане.
9. **Время каждой стадии** печатается в конце вывода и дописывается одной
   строкой в общий журнал.
10. **`ccache`** (установлен 2026-11-03). CMake не пишет обёртку компилятора в
    `compile_commands.json`, поэтому `compiler.launcher` в описании сборки
    всегда `[]`, а сама обёртка записывается отдельно, в
    `compiler.build_launcher`, только для сведения. Проверка компилятора
    не ослабляется.
11. **Порядок работ:** тесты → порядок и продолжение → экспериментальная
    половина и время стадий → одновременная проверка файлов с долей ядер →
    повторы заголовков и кэш компилятора → замер анализатора → команда для
    одного изменения → документация.

## Что не входит

- Linux (только по отдельной просьбе).
- Удаление отдельного прохода анализатора (только замер и отчёт).
- Распараллеливание медленных тестов (`slow`): отдельный вопрос, требует
  разметки «замеряет скорость машины / не замеряет».
